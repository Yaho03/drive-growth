## 1. 최신 기획서에서 달라진 기준

이전 대화의 ‘별도 캐릭터 없이 차량만 성장’보다 **새로 전달한 PDF를 이번 조사 기준으로 우선**한다. 다만 PDF 자체가 초안이고 팀 미결정 항목을 포함하므로, 아래 내용은 ‘현재 초안에 적힌 방향’이지 모든 항목이 최종 승인됐다는 뜻이 아니다.

기획서의 ‘현대차 전 차종’에는 상용차 제외, 베뉴 판매 여부·GV 계열 포함 여부 등 미결정 항목이 있다. 따라서 현재 표는 **초안에 선정한 차종 그룹 목록**으로 부른다. 이번 조사는 차량 라인업·가격표·캐릭터 설정의 사실 검증을 수행하지 않았다.

## 2. 추천하는 게임성: 출고는 확정, 꾸미기는 선택, 전투는 기록의 해석

**추천안 A: ‘르르르의 드림카 여정’**

```text
주차 중 현재 차량과 다음 출고 목표 확인
  → 평소 이동 중 허용된 범위의 주행 기록 수집
  → 주차 후 이번 기록·성장·몬스터 요약 확인
  → 경험치 누적으로 다음 탈것/차종 확정 출고
  → 원하면 무료 뽑기 또는 부품으로 꾸미기 선택
  → 다음 일상 이동을 마친 뒤 변화 확인
```

중심 재미는 ‘운전을 더 해야 보상을 받는다’가 아니라 **이미 마친 이동이 작은 이야기와 눈에 보이는 차고의 변화로 남는다**는 경험이다. 이 문장은 설계 의도이며 사용자 검증 결과가 아니다.

외부 사례의 자동 생산·자동 전투를 그대로 이식하지 않는다. 게임이 없어도 수행할 이동을 기록하고, 인터랙션은 주차 후로 모으는 것이 변환 원칙이다. 앱 종료 중 기록 접근이 보장되지 않으면 경과 시간으로 운전 기록을 만들어 보상하지 않는다.

## 4. 첫 실행·첫 주행·첫 출고를 설계하는 방법

### 4.1 첫 주행 전

- 현재 상태와 다음 목표를 한 번에 보여준다. 초반에는 뚜벅이·탈것의 역할과 자동차까지 이어지는 여정을 짧게 설명한다.
- 모든 재화·시즌·랭킹을 한꺼번에 소개하지 않는다. 첫 흐름은 ‘기록 → 정산 → 변화’만 이해해도 끝낼 수 있게 한다.
- 기능 퀘스트가 차량에서 지원되지 않아도 첫 탈것과 기본 게임 이용을 막지 않는 대안을 마련한다.

### 4.2 첫 주행 후

**권장 순서:** 이번 기록의 상태 → 획득 경험치와 이유 → 눈에 보이는 작은 변화 → 다음 목표 한 개.

첫 정산에서는 확정 색상·번호판 장식·차고 소품처럼 운과 무관한 보상을 검토한다. 초반 무료 뽑기 1회만으로 ‘성장했다’를 증명하려고 하지 않는다. 구체적인 지급 조건과 보상은 팀 결정이 필요하다.

### 4.3 첫 자동차까지의 간격

초안에서는 캐스퍼가 약 4일 뒤 등장한다. 계산상 가능한 목표지만, 자동차 공모전의 핵심 매력이 첫날에는 탈것으로만 보일 수 있다.

| 선택지 | 장점 | 비용·질문 |
|---|---|---|
| 초안 유지 + 첫날 차고 미리보기 | 뚜벅이 서사를 유지 | 미리보기와 실제 보유를 구분해야 함 |
| 첫 정산에 자동차 체험 외형 제공 | 첫날 자동차 판타지를 전달 | 체험 소유권·회수 방식이 복잡해질 수 있음 |
| 탈것 구간을 온보딩으로 압축 | 첫 차를 빠르게 경험 | 초안 레벨표·스토리 조정 필요 |

**우선 추천:** 초안의 진행표는 보존하고, 첫 정산에 확정 꾸미기와 다음 출고 차량의 미리보기를 제공하는 안을 종이 화면으로 검증한다. 이를 확인 없이 확정 기획으로 반영하지 않는다.

## 5. 경험치 표: 계산 일치와 재미 검증을 구분

초안 공식은 현재 레벨을 `L`이라 할 때 다음 레벨에 `60 + 20L` EXP가 필요하다. 레벨 1에서 목표 레벨 `T`에 도달하기 위한 누적값은 다음과 같다.

```text
누적 EXP(T) = Σ(60 + 20L), L=1…T-1
            = 10T² + 50T - 60
```

기획서의 ‘하루 30km × 평균 12 EXP/km = 360 EXP, 주 5일 = 1,800 EXP’ 가정을 그대로 대입해 재계산했다.

| 목표 | 누적 EXP | 운전한 날 수 | 주 5일 가정의 주 수 |
|---|---:|---:|---:|
| Lv10 캐스퍼 | 1,440 | 4.00 | 0.80 |
| Lv20 아반떼 | 4,940 | 13.72 | 2.74 |
| Lv50 그랜저 | 27,440 | 76.22 | 15.24 |
| Lv80 제네시스 | 67,940 | 188.72 | 37.74 |

이 값은 **초안 수식의 산술적 일치**만 보여준다. 재방문·재미·안전성 또는 실제 도달 일수를 검증한 결과가 아니다.

평균 12 EXP/km에 일일·주간 퀘스트, 몬스터, 휴식 보너스가 이미 포함됐는지 초안은 명확하지 않다. 이를 추가로 더하면 중복 계산될 수 있다. 하루 상한도 값이 없으므로 확정 도달 시점을 제시할 수 없다.

추가 검토 방법:
- 짧은 통근, 주말 운전, 장거리 이용 등 서로 다른 사용 패턴을 가정한 표를 만든다. 패턴은 예시이며 실제 이용자 통계로 표시하지 않는다.
- 거리형 기본 성장과 제한된 품질 보상을 구분하고, 총 보상 상한뿐 아니라 특정 행동을 반복해 보상을 늘릴 수 있는지 확인한다.
- 장기간 차종이 바뀌지 않는 구간에는 확정 꾸미기·차고 변화 같은 중간 보상을 검토한다.
- 초안의 D1/D7/D30 ‘시뮬레이션’ 값은 산출 모델·데이터가 이번 자료에 없으므로 재현되지 않았다. 유지율 목표나 외부 게임의 다운로드 수로 이 값을 입증하지 않는다.

## 6. 무료 가챠와 부품을 재미있는 선택으로 만드는 방법

초안의 확정 출고와 외형 뽑기 분리는 유지할 가치가 있다. 주 성장 자체를 확률에 맡기지 않기 때문이다.

| 초안 항목 | 검토 내용 | 제안 |
|---|---|---|
| 일반60/레어30/에픽9/레전드1% | 등급 합계는 100%. 개별 아이템 확률과 천장 적용 시 분포는 별도 | 등급·아이템·천장·풀 버전을 함께 정의 |
| 20회 이내 에픽 이상 | ‘이내’의 구체적 규칙이 미정 | 카운터 증가·리셋, 풀 변경 시 승계, 보장 대상 명시 |
| 도달한 모든 단계가 뽑기 풀 | 오래된 탈것·차종이 섞여 현재 원하는 보상의 체감 확률 저하 가능 | 현재 차종 위시리스트 또는 부품 확정 교환 후보 검토 |
| 중복을 부품으로 변환 | 재화만 쌓이고 사용할 곳이 없으면 실망 | 차고에서 원하는 꾸미기의 비용·진행도를 보여줌 |
| 등급별 아이템 | 초반에는 에픽·레전드 후보가 없을 수 있음 | 첫 단계부터 유효한 보장 보상 정의, 없으면 그 풀을 열지 않기 |

부품으로 특정 꾸미기를 고르는 ‘확정 교환’은 **새 제안**이다. 초안에 있는 꾸미기 사용처를 구체화할 수 있지만 팀의 승인 없이 적용하지 않는다.

보상은 저장 단계에서 확정하고 연출은 저장된 결과를 보여주는 구조를 권한다. 앱 종료·재실행으로 뽑기 결과가 바뀌거나 티켓만 사라지는 상태를 막는 것이 목표다. 법적 의무에 대한 판단은 이번 게임성 조사 범위가 아니며, ‘무료이므로 검토 불필요’라고 결론내리지 않는다.

## 7. 몬스터 전투: 기록에 의미를 주되 운전 행동을 주문하지 않기

초안의 장점은 추상적인 운전 기록을 이야기로 바꾸는 것이다. 그러나 ‘깜빡이를 켜면 스킬’, ‘급제동하면 피격’, ‘비가 오면 보스’는 실제 상황과 분리해서 해석하면 문제가 된다.

| 초안 연결 | 문제 또는 미확인 사항 | 수정 검토안 |
|---|---|---|
| 깜빡이 + 차로 변경 → 스킬 | 깜빡이 상태만으로 차로 변경·적절한 사용을 확정할 수 없음 | 검증 가능한 기록만 사용. 조작 횟수 보상은 제외 |
| 급제동 → HP 감소 | 위험 회피에 필요한 제동일 수 있음 | 게임 내 직접 처벌 대신 기록 설명·상황 한계 표시 |
| 와이퍼 → 장마 보스 | 와이퍼 사용이 실제 강우를 보증하지 않음 | 날씨 확정 표현을 피하고 게임적 테마로만 제한 |
| 전조등 → 야간 보스 | 주간에도 켜질 수 있음 | 야간 판정과 장치 상태를 구분 |
| 휴식 → 회복 | 모든 사용자에게 같은 휴게소 이용 기회가 없음 | 휴식은 선택적 칭찬. 미이용을 패널티로 만들지 않음 |
| 높은 차종 → 공격력 → 전리품·EXP | 성장 단계가 보상을 늘려 격차를 다시 키울 수 있음 | 공격력은 연출로 제한하거나, 수급 변화 범위를 별도 계산 |

**추천 표현:** 기존 초안의 ‘주행 중 화면 정지·주차 후 하이라이트’는 유지한다. 추가 제안은 주행 중 전투 음성을 제거하고, 전투 결과 계산도 주차 후 기록 기반으로 처리할지 검토하는 것이다. 플랫폼이 허용하는 기록 수집을 전제로 ‘이번 여정에서 물리친 위험 몬스터’ 요약을 보여주되, 처치 조건을 설명할 수 있어야 하고 사고 위험을 실제 측정했다는 의미로 표현하지 않는다. 기존 초안이 주행 중 전투 애니메이션을 보여준다는 뜻은 아니다.

## 8. 시즌·퀘스트·이벤트의 동기 설계

영구 성장(차량 보유·꾸미기·도감)과 시즌 진행(테마·과제)을 분리한다. 시즌이 끝나도 얻은 차와 외형을 잃지 않는 안을 권한다. 외부 게임의 환생 구조를 그대로 적용해 차고를 초기화하지 않는다.

- 8주·50티어는 운영 콘텐츠 제작량까지 확인한 뒤 확정한다. 티어가 많다는 사실이 재미를 보장하지 않는다.
- 미접속·미운전일에 연속 보상을 잃게 하기보다 횟수 누적·유연한 주간 목표를 검토한다.
- 초안의 ‘주말에 드라이브 어때요?’는 ‘이번 주 이동 기록을 확인해요’처럼 추가 운전을 권하지 않는 표현으로 바꿀 것을 제안한다.
- 출퇴근 연속일, 장거리 100km, 휴게소 방문은 이용 환경에 따른 격차가 크다. 동등한 대체 과제를 제공하거나 필수 성장에서 제외하는 안을 비교한다.
- 시즌 종료·한정 신차·눈 오는 날 보상이 급하게 운전할 이유가 되지 않도록 재획득 경로와 주차 후 확인 흐름을 검토한다.
- 자동 정산은 처음부터 제공한다. 원작의 관리자 구매·광고 시청을 ‘자동 보상 해금’으로 가져오지 않는다.

## 9. 디자인과 자산 제작 계획

새 캐릭터를 직접 만들지 않더라도 르르르의 사용 권한과 실제 사용 가능한 원본 자산은 별도 확인이 필요하다. 기존 캐릭터의 인지도는 디자인 제작이 끝났다는 뜻이 아니다.

| 화면 | 정보 우선순위 | 최소 자산·표현 후보 |
|---|---|---|
| 차고 | 현재 차량·레벨 → 다음 확정 목표 → 선택 꾸미기 | 차량 이미지, 배경 1종, 르르르 정지 포즈, 진행 바 |
| 주행 상태 | 공식 허용 범위 내 최소 상태 | 게임 애니메이션 대신 최소 표시 또는 제한 화면 |
| 정산 | 기록 상태 → 성장 변화 → 선택 행동 | 이전/이후 비교, 경험치 증가, 새 출고 강조 |
| 꾸미기·도감 상세 | 획득/미획득·다음 목표·사용처 | 동일 차량 이미지 재사용, 배지·색상 토큰·카드 |

차종을 식별할 기본 이미지와 사용자 정의 꾸미기를 분리한다. 공식 실제 색상과 게임용 색상도 구분한다. 3D 제작 없이 성립하는 구도를 먼저 검증한다.

정산은 ‘핵심 결과 확인’과 ‘원하면 꾸미기’를 분리한다. 초안의 1~2분은 목표이지 측정값이 아니다. 정산을 닫아도 보상을 잃지 않게 하고 긴 연출은 건너뛸 수 있게 하는 안을 권한다. 모든 기능을 차고·수련·정산 3개 상위 화면 아래 넣더라도, 세부 화면·오버레이·오류 상태의 디자인 작업은 남는다.

## 10. 플랫폼 확인을 먼저 통과해야 하는 부분

Pleos 공식 지침은 주행 제한을 `CarUxRestrictions`와 연계하고, 게임 등 주의 분산 활동을 유도하지 않도록 안내한다. 카테고리·지역·주행 상태에 따라 허용 범위가 달라진다. **정지 일러스트나 3분 간격 음성이라는 자체 규칙만으로 게임의 주행 중 실행이 허용된다고 볼 수 없다.** [운전 안전 설계](https://document.pleos.ai/en/docs/pleos-only/vehicle-app-planning-guide/driver-distraction-guideline) · [앱 카테고리](https://document.pleos.ai/en/docs/pleos-only/vehicle-app-planning-guide/app-category)

공식 문서는 백그라운드 작업의 조건·중단·재개와 상태 복원을 설계하도록 요구한다. 앱이 화면에서 사라진 뒤 계속 기록 가능하다는 보장은 아니다. 기록·주차 후 게임화 구조도 API 접근, 생명주기, 주최 측 허용 범위를 확인해야 한다. 카테고리 이름만 바꿔 제한을 회피하지 않는다. [앱 실행·상태 모델](https://document.pleos.ai/en/docs/pleos-only/vehicle-app-planning-guide/app-structure-screen-model)

확인 순서: 게임/기록 기능의 허용 범위 → 실제 데이터 접근 → 상태·권한 변화 시 중단과 복구 → 정산·보상 → 연출. 이번 작업은 해당 실행 검증을 하지 않았다.

## 11. 팀에서 비교할 성장안 3개

| 안 | 핵심 재미 | 첫 실행·첫 정산 | 중장기 목표 | 화면·자산·개발 부담 | 주요 질문 |
|---|---|---|---|---|---|
| **A. 드림카 여정형 — 추천** | 확정 차종 출고 + 선택 꾸미기 | 탈것 소개 → 기록 정산 → 확정 작은 보상·다음 차 미리보기 | 단계 출고, 부품 꾸미기, 도감 | 기존 3개 화면 중심. 차량 이미지·출고 연출·저장 규칙 필요 | 첫 자동차까지 기다리는 시간이 적절한가? |
| B. 차고 수집형 | 갖고 싶은 차를 목표로 선택 | 목표 차 선택 → 기록 누적 → 수집 진행도 확인 | 차고 완성, 테마 컬렉션 | 위시리스트·수집 교환·더 많은 차량 자산 | 초안의 가격순 한 줄 진행을 바꿀 것인가? |
| C. 위험 몬스터 도감형 | 매 이동의 이야기를 수집 | 기록 설명 → 몬스터 요약 → 도감 한 칸 변화 | 챕터 이야기, 몬스터 도감, 차종은 큰 이정표 | 몬스터 이미지·기록 매핑·리포트 필요 | 차량보다 몬스터가 중심이 되지 않는가? |

A는 최신 초안의 출고·가챠 방향을 가장 많이 보존한다. B는 목표 선택을 늘리지만 범위 변경이 크다. C는 매회 변화가 쉽지만 위험 감지의 정확성에 대한 오해를 피해야 한다. 어느 안도 채택 완료가 아니다.

재화는 초안의 EXP·가챠권·부품을 중심으로 검토하되, 몬스터 도감은 소비 재화보다 **수집 상태**로 분류하는 편이 명확하다. 시즌 진행도까지 포함하면 표시할 수치가 더 늘어나므로 첫 화면에 모두 노출하지 않는다.

## 12. 1차 준비에 연결할 최소 검증안

아래는 팀의 범위 결정을 돕는 제안이며 기능을 임의로 삭제하는 결정이 아니다.

1. 대표 차량·탈것과 다음 출고 한 구간으로 ‘기록 → 정산 → 외형 변화’를 실제로 연결한다.
2. 다른 단계는 데이터 목록과 개발 범위를 구분한다. 목록 19단계를 작성한 것을 전체 구현으로 보고하지 않는다.
3. 무료 뽑기·중복 변환을 넣는다면 풀의 유효성·천장·중복 결과·저장 복원을 함께 검증한다.
4. 시즌·랭킹은 제작·운영 비용을 보고 범위를 결정한다. 화면 목업만 있으면 명시한다.
5. 데모에서 레벨을 건너뛰는 기능은 시연용 입력임을 표시하고 일반 플레이 기록과 분리한다.

| 검증 질문 | 방법 | 판정 방식 |
|---|---|---|
| 첫 보상이 이해되는가? | 팀 외 관찰자에게 화면 초안을 보여주고 획득 내용·다음 목표 설명 요청 | 이해하지 못한 지점 기록. 측정 전 성공률 주장 금지 |
| 정산이 짧게 끝나는가? | 결과 확인과 선택 꾸미기의 소요 시간 따로 측정 | 1~2분 목표와 비교, 화면별 병목 기록 |
| 운전을 더 해야 한다고 느끼는가? | 보상·이벤트 문구를 읽힌 뒤 다음 행동 질문 | 추가 운전·불필요 조작을 유도하는 문구 수정 |
| 보상이 중복·유실되지 않는가? | 같은 주행 재처리, 앱 종료·재실행, 뽑기 중단 | 확정 결과와 보유량이 일치하는지 확인 |
| 저빈도 이용자도 성장하는가? | 사용 패턴별 가정·수식·캡을 공개한 계산표 | 구간별 정체 확인. 실제 유지율로 해석 금지 |

## 14. 이번 조사에서 남은 사항

- 캐릭터·차종·제네시스 이름과 이미지 사용 승인, 현재 판매 라인업·가격 순서는 미확인이다.
- 실제 SDK 신호가 운전 행동을 판정하기에 충분한지, 주행 중 기록·음성 허용 범위는 미검증이다.
- 사용자 인터뷰·직접 플레이·게임 밸런스 실험·유지율 측정은 수행하지 않았다.
- 제품·기술·검증 기준 문서는 별도로 관리되고 있다. 이번 작업에서는 이를 덮어쓰지 않고 조사 문서 2개를 추가했다. 외부 게임 조사로 기존 기능을 자동 제외하거나 구현 완료로 바꾸지 않았다.
- 팀 결정 후 해당 기준 문서에 승인된 항목만 옮기고, 이 문서는 참고·판단 근거로 유지한다.
