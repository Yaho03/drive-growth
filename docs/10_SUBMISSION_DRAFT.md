## 앱명 / 프로젝트명

드라이브 키우기

## 1. 앱 한 줄 소개

평소 이동을 차량 영입과 게임 수익으로 연결하고, 주차 후 모은 차량과 렌터카 가게를 키우는 차량용 방치형 경영 게임입니다.

## 2. 기획 배경

자동차를 좋아하는 운전자는 여러 차를 모으고 작은 가게가 커지는 경험을 즐길 수 있지만, 운전 중 화면 확인과 게임 조작을 요구하는 방식은 차량 환경에 맞지 않습니다. 드라이브 키우기는 필요한 이동을 마친 뒤 성과를 확인하는 흐름으로 자동차 수집과 가게 경영의 재미를 제공하려 합니다.

대상은 일상 또는 장거리 이동의 결과를 게임 속 성장으로 확인하고 싶은 운전자입니다. 주차 상태에서 의뢰 선택과 가게 관리를 하고 주행 중에는 게임 화면·조작·성장 연출·게임 알림을 요구하지 않는 방향으로 설계합니다. 고객 수요와 차별성은 현재 팀의 기획 가설이며 사용자 조사로 검증한 결과가 아닙니다.

## 3. 앱 주요 기능 및 차량 특화 요소

- **목적지와 연결한 탁송:** 주차 중 목적지를 선택하고 거리 조건에 맞는 무작위 의뢰 중 수익 탁송 또는 차량 구매 탁송을 고릅니다. 구매 탁송은 게임머니를 지불한 뒤 도착 확인을 거쳐 차량을 확보하는 경험입니다. 실제 운전에 따른 기본 수익과 의뢰 완료 보상을 구분합니다.
- **자동 렌터카 영업과 가게 성장:** 보유 차량을 고객 요구에 맞춰 영업에 활용하고 매출·대여 이력·가상 사고 결과를 확인합니다. 모은 재화로 차량 보유 공간을 확장하고 가게 외형·시설을 변경합니다. 시연용 시험값과 최종 게임 밸런스는 구분합니다. 다시 접속하면 저장된 기준 시각과 영업 조건에 따라 앱을 닫았던 동안의 정상·감액·상한 구간을 계산하고 확정 결과를 복원합니다. 제어된 모의 입력과 실제 저장소로 정산·복원을 검증했으며, 별도 Pleos 에뮬레이터의 SDK Back 시험에서 앱 이탈 기준 시각의 기록을 확인했습니다. [종료 영업 검증](06_VERIFICATION.md#43-utc-전진-후-대여-복구--2026-11-13)
- **차량 수집과 개별 성장:** 같은 차종도 개별 보유 차량으로 관리하며 수집·레벨·강화·수리·판매·폐차를 연결합니다. 차종별 게임 가격과 수익은 구분하고, 도감·가챠·퀘스트·업적·가게 꾸미기를 핵심 요구로 구체화합니다. 레벨 상승으로 다른 차종으로 바뀌는 구조는 사용하지 않습니다.
- **주차 후 결과 확인과 복원:** 도착·주차·조작 허용 조건을 구분하고 결과·재화·차량 변경을 한 번만 확정합니다. 결과를 바로 확인하지 않아도 다음 실행에서 조회할 수 있도록 합니다.
- **내 기록과 시연용 랭킹:** [PRD의 1차 범위](01_PRD.md#1차-랭킹-범위)에 따라 내 기록 6개 지표와 별도 예시 랭킹 화면을 제공합니다. 예시를 실제 사용자 경쟁/내 온라인 순위로 표시하지 않으며 온라인 사용자 간 순위는 향후 연결입니다. 누적 수익·주간 보상 반영 거리·과거 보유 도감 칸의 집계는 같은 PRD의 최신 사용자 기준을 따릅니다. 범위/집계 기준 확정과 구현·검증 완료를 구분합니다.
- **차량 환경에 맞춘 제한:** 실제 차량 입력과 모의 입력, 관측한 거리와 예상 경로 거리를 구분합니다. 속도 0만으로 주차를 판정하지 않으며, 확인할 수 없는 이동·도착을 만들어 보상하지 않도록 설계합니다.

차량용 앱이어야 하는 이유는 차량 상태와 주차 후 사용 시점을 연결해 이동 전후의 경험을 제공하기 위해서입니다. 다만 주행 중 백그라운드 기록의 허용 여부와 실제 지속 수신은 확인 중이며, API 존재만으로 지원을 확정하지 않습니다. 게임 내 성장·가상 사고는 실제 차량 성능·안전성이나 운전자의 사고 위험을 평가하지 않습니다.

## 4. 주요 사용 시나리오

1. 출발 전 주차·조작 허용 상태에서 가게와 보유 차량을 확인합니다. 목적지를 선택하면 거리 조건에 맞는 탁송 후보가 제시되고 원하는 의뢰를 고릅니다. 내비게이션 목적지를 자동 취득할 수 있다고 가정하지 않습니다.
2. 출발 후에는 게임 화면과 조작을 요구하지 않습니다. 허용된 방식으로 확인한 차량 입력만 기록하며 게임 조작을 위해 이동을 중단하거나 화면을 확인하도록 유도하지 않습니다.
3. 모의주행 시연에서는 기본 주행 수익, 도착이 확인된 탁송 보상, 렌터카 영업 결과를 각각 저장합니다. 실제 SDK 경로에서는 활성 의뢰에 귀속되는 도착 근거가 부족하면 의뢰를 확인 대기로 유지합니다. 결과 조회는 주차와 시스템 조작 허용을 확인한 후 열립니다.
4. 사용자가 주차 후 앱을 열면 짧은 결과 요약을 보고 새 차량을 차고에서 확인하거나 가게를 확장·꾸밉니다. 앱을 닫았다가 다시 열어도 확정 결과를 재지급하지 않고 이어서 확인합니다.

목적지 변경·구매 취소·기록 누락·저장 실패와 종료 수익의 상세 조건은 PRD와 기술 계약을 따릅니다. 첫 차량과 초기 재화는 프로필당 한 번 지급하며, 개업 선물은 첫 영업 완료 뒤의 별도 보상입니다. [첫 차량 지급 검증](06_VERIFICATION.md#56-최초-지급-확정-직후-종료와-새-프로세스-복원--2026-11-12)

최종 모의 시연에서는 픽셀 화면의 첫 지급부터 수익·구매 탁송, 종료 후 같은 프로필 복원, 무료권 차량 영입, 확장·주유소, 대여 보너스, 휴식과 일일 보상을 같은 원장으로 확인했다. 해금용 자금·과거 대여·일부 차량은 시험 준비 입력을 사용했다. [연속 실행 근거](06_VERIFICATION.md#최종-동일-모의-원장의-연속-실행--2026-11-13). 실제 SDK 도착 지급과 자연 플레이의 경제 밸런스 검증으로 확대하지 않는다.

## 5. 개발 계획

Pleos Connect의 Android Automotive OS 환경용 Kotlin 앱을 개발하고 있습니다. `app`은 화면·차량 연결·플랫폼 수명주기를, `core`는 SDK와 화면에 독립적인 게임 규칙을 맡도록 합니다. 실제 도구 버전과 재현 명령은 [개발환경 기준](05_DEVELOPMENT_SETUP.md), 데이터·상태·저장 경계는 [구조 문서](02_SYSTEM_ARCHITECTURE.md)에서 관리합니다.

## 6. 기대효과 및 발전 가능성

차량 수집과 가게 성장을 통해 이동 후 짧게 돌아볼 수 있는 즐거움을 제공하고, 차량 환경에서 시선을 요구하지 않는 사용 흐름의 가능성을 검토하려 합니다. 휴식 후 다음 출발에 적용되는 보상은 모의 입력으로 시연합니다. 보상 반영 거리에는 일일 상한을 두고, 관리 화면은 주차와 조작 허용을 확인한 뒤 제공합니다. 추가 운전 유도와 주의 분산은 별도로 점검합니다.

초기 검증에서는 첫 의뢰 선택의 이해도, 주차 후 결과의 이해도, 저장·재실행 성공, 차량 수집·가게 확장의 선호를 확인할 계획입니다. MAU·Retention Rate의 측정 자료나 산정 근거는 아직 없으며 숫자를 실적 또는 근거 있는 예측으로 기재하지 않습니다. 이후 사용자 시험과 배포 범위가 정해지면 측정 기간·대상·지표 정의를 붙여 목표를 작성합니다.

차량 종류·시설·이벤트·랭킹을 확대할 수 있으나 실제 구현 범위와 후보를 구분합니다. 차량 이미지·로고·르르르 등의 권리와 외부 서비스·개인정보 조건을 확인하고 적용하며, 실제 차종 자료와 게임 수치를 혼동하지 않도록 합니다.
