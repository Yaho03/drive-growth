# 제품 요구사항 — 렌터카 가게

결정 반영일: 2026-11-03 KST. 기준은 사용자의 최신 채팅 결정이다. 이 문서는 제품 규칙의 단일 기준이며, **기획 합의와 구현 완료를 구분한다.** 기술 계약은 [구조 문서](02_SYSTEM_ARCHITECTURE.md), 화면은 [UI·UX 명세](09_UI_UX_SPEC.md), 실제 검증 결과는 [검증 문서](06_VERIFICATION.md)를 따른다.

## 방향과 변경 이력

드라이브 키우기는 **평소 이동을 차량 영입·수익으로 연결하고, 주차 후 차량을 모으고 렌터카 가게를 확장하는 차량용 방치형 경영 게임**이다. 자동차 수집과 작은 가게가 커지는 경험이 중심이다. 대상은 일상·장거리 이동의 결과를 게임 속 사업 성장으로 확인하려는 운전자다.

이전 PDF의 선형 차종 교체·탈것 프롤로그·전투·시즌을 현재 기획으로 사용하지 않는다. 차량은 레벨 상승으로 다른 차종으로 변하지 않고, 영입·중복 보유·대여·강화·매각의 대상이 된다. 이전 계산 검토는 [게임 조사 B부](03_GAME_BENCHMARK.md)의 과거 제안으로 보존한다. 원본 PDF와 기존 구현 기록은 수정하지 않는다. 아이디어 6안 PDF 이후의 렌터카 방향과 아래 사용자 답변이 이전 초안보다 우선한다.

**손님 이야기는 넣지 않고, 가게 꾸미기에 집중한다.** 손님 리뷰·단골 여부는 영업 결과 정보로 다루며 서사·대화 콘텐츠와 구분한다. 르르르는 가게 사장 역할이며 별도 성장 주체가 아니다. 사용권·표현 방식은 확인이 필요하다.

## 핵심 흐름과 성장 전후 변화

1. 주차·조작 허용 상태에서 가게 전체와 보유 차량, 쌓인 결과를 확인한다.
2. 목적지를 선택하면 거리 조건에 맞는 무작위 탁송 목록이 나온다. 플레이어는 수익 탁송 또는 구매 탁송을 고른다.
3. 출발하면 게임 화면·조작·게임 알림을 요구하지 않는다. 자동 기록은 제품 목표이며 플랫폼 허용과 실제 지속 수신은 미확인이다.
4. 실제 이동에 따른 기본 게임머니와 탁송 완료 보상을 구분한다. 탁송 보상은 도착을 확인한 뒤 지급한다.
5. 주차·조작 허용 후 사용자가 앱을 열면 결과를 확인하고, 새 차량·영업 수익으로 차량과 가게를 성장시킨다.
6. 결과를 바로 보지 않고 종료해도 다음 실행에서 저장된 결과를 확인한다. 확인 버튼은 보상 재지급 트리거가 아니다.

실제 탑승 차량과 영입할 게임 차량은 별개다. 실제 차종 식별이나 내비게이션 목적지 자동 취득을 지원한다고 가정하지 않는다. 탁송 미선택 이동의 기본 수익 유지와 출발 전 선택을 필수 절차로 만들지 않는 처리는 제안이며, 세부 동작은 확정 전이다.

## 확정 규칙

여기서 확정은 제품 방향의 합의이며 수치·SDK 지원·제출본 구현 완료를 뜻하지 않는다.

### 탁송과 기본 주행 수익

| 항목 | 결정 |
|---|---|
| 수익 탁송 | 원하는 구매 차량이 없을 때 돈을 버는 의뢰를 선택. 도착 후 완료 보상 |
| 구매 탁송 | 제시된 차량 중 원하는 차를 선택하고 게임머니를 지불. 도착 후 해당 차량 확보 |
| 목록 | 거리 조건에 맞는 무작위 차량·의뢰 제시. 거리 구간·등장 확률·가격은 미정 |
| 기본 수익 | 탁송과 별도로 실제 운전한 만큼 게임머니 획득. 렌터카 자동 영업보다 큰 수익을 의도하며 배율은 미정 |
| 거리 상한 | 하루 주행 보상 반영 거리 최대 **500km**. 목표 거리가 아니며 일자 경계·보상 종류별 적용 범위는 미정 |
| 변경 기회 | 진행 중 목적지 재선택 또는 의뢰 포기 중 선택할 기회 1회. 조작은 주차·UX 허용 상태에서만 |
| 변경 거리 | 최초 출발지부터 중단 지점까지 **실제 이동 거리 + 중단 지점부터 새 목적지까지 예상 경로 거리** |
| 변경 불이익 | 새 거리 조건으로 목록을 다시 제시하되 차량 희귀도를 낮춤. 하락 폭·최저 등급 처리는 미정 |
| 구매 취소 | 구매 대금에서 수수료를 공제하고 환급. 수수료율·최소값은 미정 |

변경에 취소 수수료까지 함께 부과하는 것으로 해석하지 않는다. 변경 시 기존 결제금의 보류·환급·새 차량 차액 처리는 아직 미정이다. 수익 탁송의 변경·포기 금전 처리를 구매 탁송과 동일하다고 가정하지 않는다. 예상 경로 거리는 목록 생성에 쓰며 아직 운전하지 않은 거리를 기본 수익으로 지급하지 않는다.

### 렌터카 영업·차량·시설

| 항목 | 결정·남은 구분 |
|---|---|
| 고객 | 무작위 방문, 원하는 차·목적 도시 특성·용도와 보유 차량의 궁합 반영. 버스 대여 등 고객·차량 범위는 후보 |
| 배정 | 원하는 차가 없으면 비슷한 차와 불일치 불이익 또는 다음 방문. 기본 자동 배정은 제안이며 수동 개입 범위 미정 |
| 가격·수익 | 차마다 구입 가격과 대여 수익이 다르고 비싼 차량이 더 잘 버는 방향. 실제 판매가와 게임 가격을 동일시하지 않음 |
| 획득 | 가챠와 탁송 퀘스트 구매. 확률·재화·보장 규칙 미정, 현금 결제 도입으로 해석하지 않음 |
| 중복 | 같은 차종을 여러 대 소유·영업에 사용하거나 강화 재료로 사용 가능. 개별 차량 식별 필요 |
| 차량 성장 | 개별 차량 레벨 사용. 선호도·게임 연비·대여료 효과가 후보이며 산식 미정 |
| 사고 | 가상 고객의 확률형 영업 위험으로 재미 제공. 대여 수익·선호도·중고 판매가 등에 영향. 실제 운전자 사고 예측이나 평가와 무관 |
| 수리·처분 | 수리로 성능·선호도 회복, 사고 이력은 판매 가격에 영향. 이후 판매·폐차로 적절한 수익 회수. 영구 파괴 규칙은 확정하지 않음 |
| 가게 성장 | 외형·차량 보유 공간·보험 등급, 유명세에 따른 고객 요구 차량 폭과 계약 금액 확대 |
| 부대시설 | 주유소·보험 시설 등으로 고객 대상 추가 게임머니 수익. 보유 차량 수와 누적 고객 수 등의 조건으로 해금 |

‘차량 10대 이상’은 시설 해금 예시이며 확정 수치가 아니다. 실제 연비·가격 자료는 연식·트림·출처를 확인해 참고하고 게임 능력치와 구분한다. 비싼 차·높은 레벨이 실제 운전 평가를 유리하게 만들지 않는다. 강화 재료로 소비·판매·폐차한 개체가 동시에 영업하거나 다시 소비되지 않아야 한다.

### 앱 종료·휴식·복원

- 렌터카 영업은 주행 중과 앱 종료 후에도 이어지는 경험을 제공한다. 주행 중에는 정상 렌터카 수익을 적용한다.
- 종료 후 **첫 1시간은 정상 수익, 초과 시간만 감액**한다. 감액 비율은 미정이다.
- 종료 중 수익 인정에는 **최대 시간 제한을 둔다. 최대 시간은 나중에 조정**한다.
- 주차 중 앱을 계속 열어 둔 경우의 수익률, 짧게 재접속할 때 정상 수익 유예가 초기화되는 조건은 미정이다.
- 휴식 버프는 **다음 출발 때 시작**해 쉬는 동안 소모되지 않도록 한다. 휴식 횟수 자체를 제한하지 않는 방향이다. 인정 조건·중첩·효과·지속시간은 후속 밸런스 검토 대상이다.
- 앱 종료 후의 영업은 시간 차이를 재접속 시 계산하는 방식으로도 구현 가능성을 검토한다. 실제 종료 상태에서 프로세스가 계속 실행된다는 뜻은 아니다.
- 차량 기록 누락 시 정책은 미정이다. **제안:** 확인된 구간만 기본 수익에 반영하고, 도착 증거가 부족한 탁송은 확인 대기로 보존하며 차량 신호와 무관한 영업은 별도로 계산한다. 미수신 구간을 가짜 주행으로 채우지 않는다.

## 안전·기술 확인과 남은 결정

주행 중 화면을 보게 하지 않는 것이 최우선이다. 게임 UI·입력·성장 연출은 주차와 플랫폼 UX 허용 상태를 함께 확인한 후 제공한다. 속도 0·브레이크 ON만으로 허용하지 않는다. 주행 중 자동 기록과 음성의 정책 상태는 [차량 API 조사](contest/03_VEHICLE_API.md)와 [음성 정책](contest/02_PLEOS_DEVELOPMENT.md)에 따른다. 기술적으로 API가 있다는 사실을 허용 근거로 쓰지 않는다.

| 남은 항목 | 정할 내용·이유 |
|---|---|
| 목적지·도착 | 목적지 입력 출처, 예상 거리 API, 도착 반경·증거·주차 조건. 도착과 단순 휴게소 정차를 구분 |
| 변경·실패 | 구매 변경 결제 차액, 두 번째 불가피한 경로 변경, 미도착·데이터 단절·기한 경과 처리. 임의 몰수나 추가 운전 강요를 기본값으로 삼지 않음 |
| 경제 수치 | 가격·수익·수수료·희귀도 하락·가챠 확률·차량 레벨·강화·사고·수리·판매·시설 해금 |
| 시간·상한 | 하루 경계·500km 적용 수익 범위, 종료 수익 상한·감액률·유예 갱신, 시계 변경·중복 접속 |
| 휴식 | 휴게소만 인정할지 일반 주차 휴식도 인정할지, 최소 휴식·재출발·중첩·누적·소모 조건 |
| 제출 범위 | 핵심·추가 기능별 1차 표현 수준과 구현 순서. 담당·일정·시연 입력까지 합의 |
| 표현·권리 | 차량·르르르·로고 사용 조건, 대표 차종 자산, 시점·2D/3D·UI 기술 |

거리별 희귀도·수익·순위·버프가 추가 운전을 유도할 가능성은 화면 숨김과 별도로 검토한다. 이는 거리 보상이나 랭킹을 삭제한다는 결정이 아니다. 500km 상한만으로 해결됐다고 판정하지 않는다. ‘N km만 더’, 버프 만료 전 재출발을 재촉하는 표현을 피하고, 필요한 긴급 제동을 벌하거나 불필요한 차량 조작을 해금 조건으로 만들지 않는다. 일반 운전자의 휴식 권고와 직업 운전자의 법적 의무를 구분하며 근거 확인 전 주기를 단정하지 않는다.

| 도착·정산 | 확정된 도착 근거로 차량/의뢰 보상을 한 번만 지급. 기본 주행 수익과 중복 계산 없음 |
| 영업·종료 수익 | 정상·감액·상한 구간을 분리하고 같은 시간 구간 재지급 없음 |
| 보유·강화·처분 | 중복 차종을 개별 소유 차량으로 구분, 소비·판매·폐차 후 중복 사용 불가 |
| 사고·수리·시설 | 합의된 가상 규칙 적용, 사고 이력과 회복 상태 분리, 시설 조건·추가 수익 검증 |
| 화면·복원 | 주행 중 게임 사용 제한, 주차 후 보관 결과 조회, 저장 실패·종료에도 재화·차량 일관성 유지 |
| 추가 기능 | 각 기능의 규칙·성공·실패·저장 조건을 합의하고 실행 근거 확보 후 완료 판단 |
