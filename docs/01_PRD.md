# 제품 요구사항 — 렌터카 가게

결정 반영일: 2026-11-03 KST(렌터카 방향), 2026-11-04 KST(#24 기능별 규칙). 기준은 사용자의 최신 채팅 결정이다. 이 문서는 제품 규칙의 단일 기준이며, **기획 합의와 구현 완료를 구분한다.** 기술 계약은 [구조 문서](02_SYSTEM_ARCHITECTURE.md), 화면은 [UI·UX 명세](09_UI_UX_SPEC.md), 실제 검증 결과는 [검증 문서](06_VERIFICATION.md)를 따른다.

## 방향과 변경 이력

드라이브 키우기는 **평소 이동을 차량 영입·수익으로 연결하고, 주차 후 차량을 모으고 렌터카 가게를 확장하는 차량용 방치형 경영 게임**이다. 자동차 수집과 작은 가게가 커지는 경험이 중심이다. 대상은 일상·장거리 이동의 결과를 게임 속 사업 성장으로 확인하려는 운전자다.

이전 PDF의 선형 차종 교체·탈것 프롤로그·전투·시즌을 현재 기획으로 사용하지 않는다. 차량은 레벨 상승으로 다른 차종으로 변하지 않고, 영입·중복 보유·대여·강화·매각의 대상이 된다. 이전 계산 검토는 [게임 조사 B부](03_GAME_BENCHMARK.md)의 과거 제안으로 보존한다. 원본 PDF와 기존 구현 기록은 수정하지 않는다. 아이디어 6안 PDF 이후의 렌터카 방향과 아래 사용자 답변이 이전 초안보다 우선한다.

**손님 이야기는 넣지 않고, 가게 꾸미기에 집중한다.** 손님 리뷰·단골 여부는 영업 결과 정보로 다루며 서사·대화 콘텐츠와 구분한다. 르르르는 가게 사장 역할이며 별도 성장 주체가 아니다. 사용권·표현 방식은 확인이 필요하다.

### 2026-11-04 #24 결정 반영

#24에서 기능별 미정 규칙을 6묶음(탁송 예외, 렌터카 영업, 시간·상한, 차량 경제, 수집·이벤트, 휴식·연동)으로 결정했다. 출처는 #24 담당자의 채팅 결정이며 팀 회의 개최로 표시하지 않는다. 기존 확정 내용 중 달라진 항목은 다음과 같다.

| 항목 | 이전 | 변경 | 영향 |
|---|---|---|---|
| 종료 후 정상 수익 시간 | 첫 1시간 | **첫 30분.** 주차 중 앱을 켜 둔 경우도 같은 규칙 | 화면 명세의 영업 결과 상세, 검증 계획의 종료 수익 구간 재확인 필요 |
| 비싼 차의 수익 | "비싼 차량이 더 잘 버는 방향" | 시간당 기대 수익이 최저가 차량 대비 **최대 1.5배**(시험값) | 차량 데이터 계약(#27)의 가격·대여료 필드 |
| 랭킹 지표 | 누적 게임머니·차량 개수·가장 비싼 차 | 주행거리를 포함한 **6개 부문**, 주행거리 부문은 상한·주간 초기화 | 랭킹 화면·온라인 범위(#25) |
| 휴식 인정 | 휴게소만 인정할지 미정 | **휴게소·졸음쉼터만** 인정 | 위치 판정 근거(#13) 필요 |

**표기:** 아래 표의 `시험값`은 밸런스 확인 전 임시 숫자이며 실측·최종 밸런스가 아니다. `보류`는 1차 범위에서 다루지 않고 재논의 조건을 남긴 항목이다. `미정`은 아직 결정하지 않은 항목이다.

## 핵심 흐름과 성장 전후 변화

1. 주차·조작 허용 상태에서 가게 전체와 보유 차량, 쌓인 결과를 확인한다.
2. 목적지를 선택하면 거리 조건에 맞는 무작위 탁송 목록이 나온다. 플레이어는 수익 탁송 또는 구매 탁송을 고른다.
3. 출발하면 게임 화면·조작·게임 알림을 요구하지 않는다. 자동 기록은 제품 목표이며 플랫폼 허용과 실제 지속 수신은 미확인이다.
4. 실제 이동에 따른 기본 게임머니와 탁송 완료 보상을 구분한다. 탁송 보상은 도착을 확인한 뒤 지급한다.
5. 주차·조작 허용 후 사용자가 앱을 열면 결과를 확인하고, 새 차량·영업 수익으로 차량과 가게를 성장시킨다.
6. 결과를 바로 보지 않고 종료해도 다음 실행에서 저장된 결과를 확인한다. 확인 버튼은 보상 재지급 트리거가 아니다.

실제 탑승 차량과 영입할 게임 차량은 별개다. 실제 차종 식별이나 내비게이션 목적지 자동 취득을 지원한다고 가정하지 않는다. 탁송 미선택 이동의 기본 수익 유지와 출발 전 선택을 필수 절차로 만들지 않는 처리는 제안이며, 세부 동작은 확정 전이다.

## 확정 규칙

여기서 확정은 제품 방향의 합의이며 수치·SDK 지원·제출본 구현 완료를 뜻하지 않는다.

### 탁송과 기본 주행 수익

| 항목 | 결정 |
|---|---|
| 수익 탁송 | 원하는 구매 차량이 없을 때 돈을 버는 의뢰를 선택. 도착 후 완료 보상 |
| 구매 탁송 | 제시된 차량 중 원하는 차를 선택하고 게임머니를 지불. 도착 후 해당 차량 확보 |
| 목록 | 거리 조건에 맞는 무작위 차량·의뢰 제시. 거리 구간·등장 확률·가격은 미정 |
| 기본 수익 | 탁송과 별도로 실제 운전한 만큼 게임머니 획득. 렌터카 자동 영업보다 큰 수익을 의도하며 배율은 미정 |
| 거리 상한 | 하루 주행 보상 반영 거리 최대 **500km**. 목표 거리가 아니다. **기본 주행 수익에만 적용**하며 탁송 완료 보상(의뢰 단위)과 렌터카 영업 수익(시간 단위)에는 적용하지 않음 |
| 하루 기준 | 기기 현지 시각 **자정(00:00)** 에 초기화. 자정을 넘기는 주행은 **출발한 날**로 계산 |
| 변경 기회 | 진행 중 목적지 재선택 또는 의뢰 포기 중 선택할 기회 1회. 조작은 주차·UX 허용 상태에서만 |
| 두 번째 변경 | 불가. 변경 기회를 쓴 뒤에는 **포기만** 가능(구매 탁송은 수수료 공제 후 환급). 앱이 불가피성을 판정하지 않음 |
| 변경 거리 | 최초 출발지부터 중단 지점까지 **실제 이동 거리 + 중단 지점부터 새 목적지까지 예상 경로 거리** |
| 변경 불이익 | 새 거리 조건으로 목록을 다시 제시하되 차량 희귀도를 **1단계** 낮춤(시험값). 최저 등급 처리는 미정 |
| 구매 탁송 변경 | 기존 결제금은 보류하고, 새 목록에서 차량을 고르면 **차액만 추가 결제 또는 환급**. 변경에는 취소 수수료를 부과하지 않음 |
| 수익 탁송 변경 | 새 목록에서 다시 선택하고 완료 보상은 **새 의뢰 기준**. 이미 운전한 거리는 기본 수익으로 지급됐으므로 별도 정산 없음 |
| 수익 탁송 포기 | **벌금 없음.** 완료 보상만 지급하지 않음 |
| 구매 취소 | 구매 대금에서 수수료 **10%**(시험값)를 공제하고 환급. 최소값은 미정 |
| 미도착 | 목적지가 아닌 곳에 주차하면 탁송은 진행 중으로 유지. **24시간**(시험값) 안에 도착하면 완료. 기한이 지나면 구매 탁송은 **수수료 없이 전액 환급**, 수익 탁송은 소멸(벌금 없음) |
| 기록 단절 | 확인된 구간만 기본 수익에 반영. 도착 증거가 부족한 탁송은 **확인 대기**로 보관하고 다음 주차 시 다시 확인. 끝내 확인되지 않으면 미도착 규칙 적용. 미수신 구간을 가짜 주행으로 채우지 않음 |

예상 경로 거리는 목록 생성에 쓰며 아직 운전하지 않은 거리를 기본 수익으로 지급하지 않는다. 탁송 예외 처리는 임의 몰수나 추가 운전 강요를 기본값으로 삼지 않는다.

### 렌터카 영업·차량·시설

| 항목 | 결정 |
|---|---|
| 고객 | 무작위 방문, 원하는 차·목적 도시 특성·용도와 보유 차량의 궁합 반영. 방문 빈도는 **시간당 2명**에서 시작해 가게 유명세에 따라 증가(시험값) |
| 차량 유형 | **소형, 세단, SUV, 승합, 친환경(전기·수소)** 5가지. 고객 요구와 궁합 판정에 사용 |
| 배정 | **전부 자동 배정.** 수동 개입은 차량별 **"영업 쉬기" 스위치**(강화·수리 대상 제외용)만 제공 |
| 궁합 | 3단계. ① 원하는 차종 그대로: 대여 수익 **+20%**·리뷰 상승 ② 같은 유형의 다른 차: 대여 수익 **−20%**(불일치 불이익) ③ 유형 불일치: 대여하지 않고 고객이 다음에 다시 방문(시험값) |
| 대여 시간 | 고객마다 **1시간·3시간·6시간** 중 하나. 대여 종료 후 **반납 이동 시간** 15분·30분·1시간(시험값)이 추가되며, 대여·반납 중인 차량은 다른 고객을 받지 않고 반납 이동 중에는 수익이 없음 |
| 대형 고객 | 버스 대여 등은 1차 **보류.** 후속 후보로 유지 |
| 가격·수익 | 차마다 구입 가격과 대여 수익이 다름. 비싼 차는 1회 대여 수익이 크지만 찾는 고객이 드물고, 저렴한 차는 수요가 많다. 그 결과 **시간당 기대 수익은 최저가 차량 대비 최대 1.5배**(시험값)로 비싼 차가 조금 더 번다. 게임 가격은 별도 게임용 가격표를 쓰며 실제 판매가와 동일시하지 않음(순서만 대략 참고) |
| 획득 | 가챠와 탁송 퀘스트 구매. 가챠 규칙은 아래 「시작 경험과 주요 기능」 참조. 현금 결제 없음 |
| 중복 | 같은 차종을 여러 대 소유·영업에 사용하거나 강화 재료로 사용 가능. 개별 차량 식별 필요 |
| 차량 성장 | 개별 차량 레벨 사용. 레벨당 **대여료 +2%**·고객 선호도 상승(시험값). **최대 레벨은 모든 차량 20으로 동일.** 게임 연비 효과는 채택하지 않음 |
| 강화 | 기본 레벨업은 **게임머니**로 한다. **같은 차종 중복 차량**을 재료로 쓰면 즉시 **+3레벨**(시험값), 재료 차량은 소멸. 대여·반납 중인 차량은 재료로 쓸 수 없음 |
| 사고 | 가상 고객의 확률형 영업 위험. 대여 1회당 기본 **3%**(시험값)이며 모든 차량에 같은 기본 확률. **가상 고객의 면허 취득 기간이 짧을수록, 나이가 어릴수록** 사고율 상승(가산 폭 미정). 실제 운전자(유저)의 정보는 사용하지 않음. 가게의 대여 조건(나이·면허 제한) 설정 기능은 두지 않음 |
| 사고 결과 | 해당 대여 수익 **50%**, 차량은 **수리 필요** 상태(영업 불가). 차량을 영구 파괴하지 않음 |
| 수리 | 게임머니로 즉시 수리, 비용은 **차량 가격의 5%**(시험값). 수리 후 영업 가능 상태로 회복하되 **사고 1회당 대여료 −3% 영구 감소, 최대 −15%**(시험값). 사고 이력은 보존 |
| 판매 | 판매가 = **구매가의 60%**, 사고 1회당 **−5%p**, 최저 30%(시험값). 레벨이 높으면 소폭 가산(가산 폭 미정) |
| 폐차 | **사고 3회 이상** 차량은 판매 불가, 폐차만 가능. 폐차 시 **구매가의 20%** 지급(시험값) |
| 가게 성장 | 외형·차량 보유 공간·보험 등급, 유명세에 따른 고객 요구 차량 폭과 계약 금액 확대 |
| 부대시설 | **주유소:** 보유 차량 5대에서 해금, 대여 1회마다 추가 게임머니 / **보험 시설:** 누적 고객 100명에서 해금, 사고 손실 절반 / **세차장:** 가게 레벨 3에서 해금, 리뷰 상승(해금 조건·효과 모두 시험값) |

실제 연비·가격 자료는 연식·트림·출처를 확인해 참고하고 게임 능력치와 구분한다. 비싼 차·높은 레벨이 실제 운전 평가를 유리하게 만들지 않는다. 강화 재료로 소비·판매·폐차한 개체가 동시에 영업하거나 다시 소비되지 않아야 한다. 가상 사고와 고객 위험도는 게임 사건으로 표시하며 특정 나이·운전 경력 집단을 깎아내리는 문구 대신 중립적인 "보험 위험도" 표현을 쓴다.

### 앱 종료·휴식·복원

- 렌터카 영업은 주행 중과 앱 종료 후에도 이어지는 경험을 제공한다. 주행 중에는 정상 렌터카 수익을 적용한다.
- 주차 후 **첫 30분은 정상 수익**, 초과 시간은 **정상 수익의 30%** 로 감액한다(시험값). 앱을 꺼 둔 경우와 주차 중 앱을 켜 둔 경우에 같은 규칙을 적용한다. 앱을 켜 두는 것이 이득이 되지 않게 한다.
- 주차 후 수익 인정은 **최대 8시간**(시험값)까지이며 이후에는 쌓이지 않는다.
- 정상 수익 구간은 **마지막 주행이 끝난 시점부터 한 번만** 계산한다. 앱을 잠깐 열었다 닫아도 다시 시작되지 않는다.
- 기기 시계가 **뒤로 가면** 그 구간은 0으로 처리한다. **앞으로 크게 바뀌면** 최대 인정 시간까지만 계산한다.
- 1차는 **차량(기기) 1대 기준**이다. 여러 기기 동시 접속은 휴대폰 연동과 함께 후속 검토한다.
- 앱 종료 후의 영업은 시간 차이를 재접속 시 계산하는 방식으로도 구현 가능성을 검토한다. 실제 종료 상태에서 프로세스가 계속 실행된다는 뜻은 아니다.
- 차량 기록 누락 시에는 확인된 구간만 기본 수익에 반영하고, 도착 증거가 부족한 탁송은 확인 대기로 보존하며, 차량 신호와 무관한 영업은 별도로 계산한다. 미수신 구간을 가짜 주행으로 채우지 않는다.

**휴식 버프**

| 항목 | 결정 |
|---|---|
| 인정 장소 | **휴게소·졸음쉼터만.** 일반 주차는 휴식으로 인정하지 않음. 위치 판정 가능 여부는 #13 확인 대상이며, 판정할 수 없는 환경에서는 버프가 발생하지 않음 |
| 인정 조건 | 직전에 **1시간 이상 운전**한 뒤 해당 장소에서 **5분 이상 주차**(시험값) |
| 효과 | **기본 주행 수익 1.5배, 20분**(시험값). 하루 500km 상한은 그대로 적용 |
| 시작·소모 | 휴게소·졸음쉼터를 **벗어나 출발하면 자동으로 시작**. 별도 보관·사용 버튼 없음. 쉬는 동안에는 소모되지 않음 |
| 중첩 | 중첩하지 않음. 다시 휴식하면 남은 시간이 20분으로 갱신 |
| 횟수 | 횟수 제한 없음(인정 조건으로 반복 방문을 막음) |

### 시작 경험과 주요 기능

| 항목 | 상태 |
|---|---|
| 최초 차량 | 튜토리얼 후 캐스퍼·아반떼 중 선택하는 안. 두 차종이 후보이며 연식·트림·밸런스 미정 |
| 첫 영업 보상 | 새 차 **뽑기권 1장.** 르르르의 친구가 찾아와 **개업 기념 선물**로 주는 연출(가게 개업 온보딩 연출이며 손님 서사와 구분) |
| 첫 성장 | 새 차 확보·주차 공간 확장·간판/가게 꾸미기를 경험하게 함. 순서·비용 미정 |
| 가챠 | 뽑기권은 **게임머니로 구입**, 현금 결제 없음. 확률 **일반 74.7% · 고급 20% · 희귀 5% · 전설 0.3%**(시험값). 비싼 차일수록 희귀. 가게 레벨에서 해금된 차량만 등장 |
| 가챠 보장 | **30회 안에 희귀 이상 1대 보장**(시험값, 이후 조정 가능). 남은 횟수를 화면에 표시하고 뽑기 목록이 바뀌어도 횟수 유지. 앱 내 확률 공개 |
| 퀘스트 | 일일 3개·주간 3개. **주행 거리 조건 없음.** 예: 결과 확인하기, 차량 1대 레벨업, 고객 5명 받기 |
| 업적 | 보유 차량 수·누적 고객 수·가게 레벨·도감 완성률. **운전 거리 업적 없음** |
| 도감·가게 꾸미기 | 핵심 요구. 각각 상세 규칙·제출 구현 범위·순서는 추가 구체화 |
| 차량 꾸미기 | 가게 꾸미기보다 낮은 우선순위. 필수 핵심으로 확정하지 않음 |
| 이벤트 | **주말 이벤트·시즌 제외.** 주행 수익 배수 이벤트는 두지 않음. 휴식 보상은 위 휴식 버프 규칙을 따름. 특별 고객 이벤트는 후보 |
| 랭킹 | 6개 부문: **가게 레벨, 도감 수집 수, 보유 차량 수, 누적 게임머니, 주행거리, 가장 비싼 차.** 주행거리 부문은 하루 500km 상한을 적용하고 **매주 초기화.** 온라인 집계·서버 범위·동률 처리는 미정 |
| 휴식·휴게소 음성 | 검토 기능. 유형별 주행 허용·위치 접근 확인 필요 |
| 친구 가게·선물 | 1차 **보류.** 랭킹 온라인 범위와 함께 후속 검토 |
| 휴대폰 연동 | 1차 **보류**(계정·서버 필요). 운전하지 않는 날 영업·꾸미기 후보로 유지 |
| 손님 서사·시즌 | 제외. 리뷰·단골 정보와 이벤트까지 제외하는 뜻은 아님 |

최대한 많은 기능을 포함하려는 사용자 선호를 유지한다. 이 목록 전체를 1차 구현 확정이나 완료로 표시하지 않으며 임의로 핵심 기능만 남기고 나머지를 보류하지 않는다. 위 `보류` 항목은 #24에서 명시적으로 결정한 것이다.

## 안전·기술 확인과 남은 결정

주행 중 화면을 보게 하지 않는 것이 최우선이다. 게임 UI·입력·성장 연출은 주차와 플랫폼 UX 허용 상태를 함께 확인한 후 제공한다. 속도 0·브레이크 ON만으로 허용하지 않는다. 주행 중 자동 기록과 음성의 정책 상태는 [차량 API 조사](contest/03_VEHICLE_API.md)와 [음성 정책](contest/02_PLEOS_DEVELOPMENT.md)에 따른다. 기술적으로 API가 있다는 사실을 허용 근거로 쓰지 않는다.

| 남은 항목 | 정할 내용·이유 |
|---|---|
| 목적지·도착 | 목적지 입력 출처, 예상 거리 API, 도착 반경·증거·주차 조건. 도착과 단순 휴게소 정차를 구분(#13) |
| 휴식 장소 판정 | 휴게소·졸음쉼터 위치 판정 방법과 데이터 출처(#13). 판정 불가 환경의 안내 문구 |
| 탁송 수치 | 거리 구간·등장 확률·탁송 가격, 기본 주행 수익 배율, 희귀도 최저 등급 처리, 취소 수수료 최소값 |
| 차량 수치 | 게임용 가격표 실제 값, 사고율 가산 폭, 판매 시 레벨 가산 폭 |
| 탁송 미선택 | 탁송을 고르지 않은 이동의 처리(기본 수익 유지 제안) |
| 랭킹·이벤트 | 랭킹 온라인 집계·동률 처리, 특별 고객 이벤트 채택 여부 |
| 제출 범위 | 핵심·추가 기능별 1차 표현 수준과 구현 순서. 담당·일정·시연 입력까지 합의(#25) |
| 표현·권리 | 차량·르르르·로고 사용 조건, 대표 차종 자산, 시점·2D/3D·UI 기술(#19) |

거리별 희귀도·수익·순위·버프가 추가 운전을 유도할 가능성은 화면 숨김과 별도로 검토한다. 이는 거리 보상이나 랭킹을 삭제한다는 결정이 아니다. 500km 상한만으로 해결됐다고 판정하지 않는다. 주행거리 랭킹은 상한과 주간 초기화를 적용하고, 휴식 버프는 장시간 운전 후에만 인정한다. ‘N km만 더’, 버프 만료 전 재출발을 재촉하는 표현을 피하고, 필요한 긴급 제동을 벌하거나 불필요한 차량 조작을 해금 조건으로 만들지 않는다. 일반 운전자의 휴식 권고와 직업 운전자의 법적 의무를 구분하며 근거 확인 전 주기를 단정하지 않는다.
