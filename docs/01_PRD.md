# 제품 요구사항과 게임 기획

이 문서는 제품 범위·화면·콘텐츠 결정의 기준이다. 기획서의 제안, 사용자 확정, 구현, 실행 검증을 구분한다. 공식 API 근거는 [차량 API와 설계 조건](contest/03_VEHICLE_API.md), 차종 자료는 [vehicles.csv](data/vehicles.csv)에서 관리한다.

이번 원격 초기 게시에는 문서와 기본 설정만 포함한다. 아래 구현 관련 설명은 별도 로컬 작업의 기록이며 `app/src`·`core/src` 소스는 이번 게시 대상이 아니다. 이후 소스 게시 시 실제 구현과 검증 상태를 다시 맞춘다.

## 최신 기획서 확인

2026-11-03 작성된 `docs/contest/드라이브키우기_게임기획서.pdf`의 8페이지 전체 텍스트와 3페이지 성장 도표를 확인했다. 원본은 수정하지 않았으며 로컬에만 보관하고 GitHub에 게시하지 않는다. 파일 식별 SHA-256: `ed3e5a08d92d69ab6e46505fdf9e054992b14e1a32bf9b270ae628dc8eaf5ceb`.

새 문서는 **팀 공유용 초안**이다. 문서 안의 제안과 체크리스트를 사용자 실행 지시 또는 구현 완료로 취급하지 않는다.

## 사용자 결정과 남은 확인

- 공통 확정: Pleos Connect 차량용 앱, 주행 중 자동 기록·게임 조작 없음, 주차 후 정산·성장·수집 확인, 저장·복원. 게임의 운전 평가를 검증된 안전성 지표로 표현하지 않는다.
- 이전의 ‘같은 차종을 계속 키움’은 최신 사용자 답변으로 대체되었다. 차량 레벨·차종이 운전 평가를 유리하게 하지 않는 원칙은 유지한다.
- 최신 PDF 제안: 르르르 주인공, 몬스터 자동 전투, 뚜벅이→탈것→현대차→제네시스의 선형 성장, 높은 차종의 공격력 증가.
- **최신 사용자 확정(2026-11-03):** 새 기획서처럼 캐스퍼에서 아반떼·제네시스 등 다음 차종으로 바뀌는 성장 구조다. 차종 조사의 목적도 이 단계 구성이다. 단계·경험치·가챠·보상 수치는 새 기획서와 [방치형 게임 적용 문서](03_GAME_BENCHMARK.md)에 기준안이 작성돼 있다. 이를 토대로 미기재 규칙을 보완하며, 최종 밸런스 검증과 캐릭터·이미지 사용권 확인은 별도로 남는다. 아래 차량 성장 상세와 [차량 조사 범위](04_VEHICLE_RESEARCH.md)를 참조한다. 이번 차량 정리 요청은 문서 작업이며 구현 완료를 뜻하지 않는다.
- 사용자 범위 선호: 휴게소 음성, 랭킹, 수집, 기능 퀘스트 등을 임의로 보류하지 않고 최대한 포함한다. 구현 순서를 정하는 것과 기능을 제외하는 것은 다르다.

## 수정 제안과 검증 조건

1. **필요한 제동을 벌주지 않는다.** 속도 변화만으로 위험운전·불필요한 급제동을 판정할 수 없다. 급제동 시 HP 감소, ‘급제동 0회로 100km’ 성공 조건은 재설계한다. 분석 이벤트와 게임 보상 판정을 분리한다.
2. **불필요한 주행·기능 사용을 요구하지 않는다.** 크루즈 켜기·차로 변경을 필수 튜토리얼 관문으로 두지 않는다. 상황·지원 여부에 따른 건너뛰기와 주차 중 설명으로 대체하는 안을 검토한다. 거리·연속일·시즌 마감·주말 권유가 추가 운전을 유도하는지도 확인한다.
3. **관측 신호와 해석을 구분한다.** 깜빡이 신호는 차로 변경 완료, 와이퍼는 강우, 전조등은 야간, 오래 운전한 시간은 실제 졸음의 확정 근거가 아니다. 보스는 게임적 표현이며 실제 위험 진단으로 표시하지 않는다.
4. **정차와 주차를 구분한다.** 10절의 ‘주차·정차 중 안내’는 13절의 신호 대기 조작 금지와 충돌한다. 조작·가챠·상세 퀘스트는 확인된 주차 상태와 시스템 UX 허용 조건을 함께 충족할 때만 제공한다.
5. **전투 성장과 평가의 관계를 정의한다.** 높은 차종의 공격력이 처치 수·EXP·시즌 진행도를 늘린다면 보상에 간접 차이가 생긴다. 운전 평가·게임 진행·경쟁 순위를 각각 정의하고 외형 가챠가 이 계산에 영향을 주지 않는지 검증한다.
6. **권리 확인과 공개 범위를 구분한다.** 차종 조사 자료는 게임 자산 사용 허가가 아니다. 원본 팀 공유 PDF에는 작성자 이름이 있으므로 심사 제출본은 공식 익명 소개 조건에 맞춰 별도로 준비한다. 문의 이메일은 자동 발송하지 않는다.

## 수치 확인 결과

초안 성장 수식과 단계별 누적 EXP의 산술 일치만 확인했다. 공식·누적값·주행량 가정별 도달 시간과 보상 중복 계산 검토는 [게임 비교·적용 문서](03_GAME_BENCHMARK.md)의 B부 5~6절에서 관리한다. 실제 성장 속도·재미·유지율 검증은 남아 있으며 최종 수치가 채택되면 이 PRD의 기준으로 옮긴다.

MAU·리텐션은 검증된 성과가 아니라 초안의 가정이다. 현재 핵심 엔진의 시험용 경험치·레벨 규칙은 새 기획의 성장표를 구현한 것으로 해석하지 않는다.

## 로컬 선행 화면 구현 기록

`DashboardView`에는 임시 차량 도형을 사용하는 홈·주행 제한·정산·차고·기록·튜토리얼·기기 내 랭킹 표현이 있다. 독립 Kotlin 컴파일만 확인했으며 Activity 연결·실데이터·화면 실행 검증 완료를 의미하지 않는다. 새 기획의 3개 주요 화면(차고→주행→정산)에 도감·가챠·랭킹을 하위 화면으로 배치하는 안을 검토한다.

## 차량 성장 상세

차종 교체 성장의 상세 설계와 남은 결정이다. 차량은 성장 보상·시각적 진행의 중심이며 르르르의 역할·디자인·사용권은 별도 검토 대상이다. 실제 탑승 차종 연동은 별도 후보이고 게임 차종이 실차 소유나 성능 개선을 뜻하지 않는다. 차종별 사실은 CSV에서 관리한다.

| 경험치 | 주차 후 정산 | 흐름 확정; 성장 공식 작성·산술 검증됨. 일일 상한·보너스 포함 범위·최소 기록 조건은 보완 필요 |

PDF의 레벨표·누적 경험치·보상·가챠 확률·천장·시즌 수치는 이미 작성된 기획 기준안이다. [방치형 게임 적용 문서](03_GAME_BENCHMARK.md)의 B부 5~6절과 [제품 문서의 수치 확인 결과](01_PRD.md#수치-확인-결과)를 참조하며, 같은 표를 이 문서나 사실 CSV에 중복 작성하지 않는다. 성장 공식과 단계 진입 누적 EXP의 산술 일치는 확인됐고, 도달 일수는 주행량 가정에 따른 추정이다. 기존 수치를 처음부터 다시 정하는 대신 일일 상한·보너스 중복 계산 여부·가챠 보장 카운터 등 비어 있는 규칙을 보완한다. 실제 성장 속도 검증과 최종 밸런스 확정은 별도이며 현재 코드의 시험용 수치를 기획 기준안으로 대체하지 않는다.

### 핵심 흐름과 성장 전후 변화

1. **주차·조작 허용 상태:** 현재 차종과 진행 상태 확인. 미정 퀘스트·가챠를 필수 화면으로 만들지 않는다.
2. **주행 시작:** 게임 조작과 성장 연출을 닫고 기록 모드로 전환. 기록 가능 여부와 입력 출처를 구분한다.
3. **주행 중:** 사용자 행동 요구 없이 허용된 데이터만 수집한다. 차종 교체·보상·희귀 획득 팝업을 띄우지 않는다.
4. **주차 확인:** 기록의 유효성·중복 여부를 확인하고 정산한다. 기록 부족은 ‘확인 불가’로 표시하며 완벽한 안전운전으로 판정하지 않는다.
5. **정산:** 경험치와 진행 변화 확인. 확정된 해금 조건을 만족할 때만 다음 차종 지급 및 교체.
6. **차고 복귀:** 새 차종과 이력 확인. 별도 조작 없이 다음 주행에서도 선택 상태를 일관되게 유지한다.

| 상황 | 성장 전 | 성장 후 | 상태 |
|---|---|---|---|
| 같은 단계 내 성장 | 현재 차종·진행도 | 진행도/레벨 변화 | 세부 표현 미정 |
| 다음 단계 도달 | 현재 차종 | 다음 차종의 이름·외형으로 교체 | 구조 확정, 연출 미정 |
| 꾸미기 획득 | 기본 외형 | 색상·장식 등 변화 가능 | 후보; 확정 보상 아님 |
| 르르르 이야기 | 기존 이야기 장면 | 다음 장면·반응 후보 | 권리·디자인·범위 미정 |

이전 차종을 새 차종처럼 변형해서 보여주는지, 차고에서 교체하는지, 출고 연출을 쓰는지는 미결정이다. 차체 이미지와 이름을 함께 바꿔 다른 차종으로 진행했다는 점이 읽히게 한다. 가짜 숫자를 실제 제원처럼 표시하지 않는다.

### 차종별 차이와 공통 규칙

차종별 차이는 확인된 이름·차체·외형·이야기 단계 및 승인된 아트에 둔다. 크기나 동력 방식에 맞춘 외형 차이는 가능하지만, 기능 지원은 실제 차량 입력의 Capability로 판단한다.

공통 규칙:

- 현실 가격·출력·최고속도에서 게임 등급·보상 배율·안전운전 점수를 자동 계산하지 않는다.
- PDF의 ‘가격순 차종’은 미확정 순서 제안이며 가격 수집으로 능력치 표를 만들지 않는다.
- PDF의 ‘더 높은 차종 → 공격력 상승’은 현재 미채택 검토 항목이다. 전투가 필요하다면 게임 성장값과 실차 성능을 분리해 다시 결정한다.
- 차종을 교체해도 동일한 기록의 운전 평가가 유리해지지 않는다. 공격력·전투 결과가 게임 XP에 미치는 영향은 별도 결정·검증 대상이며 게임 레벨을 안전 자격으로 표시하지 않는다.
- 수소차·전기차·고성능차·고가차를 안전하거나 우월한 운전의 증거로 취급하지 않는다.
- 주차 확인·중복 지급 방지·기록 누락·재시작 정책은 모든 차종에 동일하게 적용한다.

### 화면별 표현

새 PDF는 차고·수련·정산 3화면을 제시한다. 현재 구현에는 홈·차고 구분이 관찰되어 아래는 두 구조를 연결한 문서다. 화면 수를 새로 확정하거나 코드를 수정한 것은 아니다.

| 화면 | 표현할 정보 | 제한·미결정 |
|---|---|---|
| 홈 | 현재 차종·진행 상태·최근 정산 요약 | 차고와 통합 여부 미정. 추가 주행 유도 문구 금지 |
| 수련 | 기록 상태, 입력 이상 여부 | 게임 조작·진행 바 경쟁·차종 해금 연출 없음. 정지 그림도 플랫폼 허용 확인 필요 |
| 정산 | 이번 기록·지급 결과·진행 변화·조건 충족 시 다음 차종 | 반복 진입으로 중복 지급 금지; 정산 시 차종 교체 연출 |
| 차고 | 현재 차종과 승인된 외형 | 보유 도감·이전 차 재선택·가챠·꾸미기는 포함 범위·구현 순서 검토 중 |

운전 중 0km/h 또는 브레이크 ON만으로 게임 UI를 허용하지 않는다. 주차와 플랫폼 `CarUxRestrictions` 등 실제 제한 상태를 함께 판단한다. 데이터 부재 시 게임 조작을 허용하는 방향으로 추정하지 않는다. [기존 차량 API·설계 조건](contest/03_VEHICLE_API.md) 5절 참조.

### 불필요한 주행·위험 행동 유인 검토

새 PDF의 안전 의도와 충돌할 수 있는 부분을 남겨 둔다. **아래는 보완 제안이며 수치·산식을 확정한 것이 아니다.** 원본을 몰래 수정하거나 기능을 완료했다고 표시하지 않는다.

| 원안 위치·내용 | 문제 | 보완 방향 |
|---|---|---|
| 3~4·6쪽: 하루 30km 가정, km당 경험치, 몇 주 후 다음 차 | 목표 때문에 더 운전할 수 있음 | 평소 이동만 대상으로 하고 추가 거리로 성장 이익이 계속 늘지 않는 정산 규칙 검토 |
| 6쪽: 장거리 100km·출퇴근 연속일·주간 100km | 주행 의무·스트릭 손실 유인 | 비운전일 손실·최소 거리 해금 제거, 주차 중 안내 확인 등 대안 검토 |
| 7쪽: ‘오늘 드라이브 어때요?’·주말 보너스 | 불필요한 출발 유도 | 문구·시간대 이동 보상 미채택. 기존 이동의 정산 표현만 변경하는 안 검토 |
| 2·7쪽: 날씨 보스·한정 아이템 | 위험한 날씨 운전 동기 | 날씨에 따라 희귀 보상이 유리해지는 구조 제외 검토 |
| 2·7쪽: 급제동 HP 감소·피격 음성 | 필요한 긴급제동을 회피할 수 있음 | 회피 불가능한 사건을 벌하지 않기; 즉시 게임 감점·피격 반응 미채택 검토 |
| 2·6쪽: 차로 변경·기능 켜기 보상 | 불필요한 조작 유도 | 운전 행동 수행을 해금 필수 조건으로 만들지 않기 |
| 2·6쪽: 휴게소 방문 보상 | 우회·방문 반복 유인 | 휴식은 게임 외 안전 안내로 분리하거나 동등한 주차 휴식 인정 검토 |
| 4~5쪽: 확률형 수집·시즌 한정 보상 | 마감 전 반복 운전 유인 | 1차 포함 범위는 팀 결정; 비운전일 불이익·추가 주행 이익 검토 |

일일 상한 하나만으로 이런 유인이 해소됐다고 판정하지 않는다. 구체적 산식·최소 표본·미지원 기능 처리·백그라운드 실행은 팀 결정과 플랫폼 시험이 필요하다. 주행 중 기록을 구현할 수 있다는 가정과 실제 SDK 지원·승인은 별개다.

### 대표 차종 하나로 먼저 검토할 것

**1차 시각 검토 후보: `hyundai_casper`.** 새 원안의 첫 자동차이므로 출고·단계 진입 장면을 검토하기 좋고, 세대·동력 혼동을 피하기 위해 일렉트릭과 구분할 수 있다. 낮은 가격·출력이 낮은 게임 등급의 근거라는 의미는 아니다. 최종 선택과 외형은 팀 확정 전이다.

이번에는 문서만 요청했으므로 시안·이미지·목업을 제작하거나 시각 검증을 완료하지 않았다.

후속 검토 순서:

1. 해당 차종의 연식·트림·외형 식별점과 자산 사용 조건 확인.
2. 같은 자산 하나로 기본 상태·레벨 변화·꾸미기 후보를 비교하고 홈·정산·차고에서 가독성 확인. 그림체·카메라 각도·색감은 미결정.
3. 다음 차종 해금은 우선 텍스트/중립 자리표시자로 흐름만 검토. 다른 차종 전체 자산을 동시에 제작하지 않음.
4. 첫 차 스타일과 화면 배치가 검토된 뒤 두 번째 차종을 제작해 실제 교체 전후 차이가 읽히는지 확인.
5. 수련 화면에서 조작·획득 유혹이 생기지 않는지 별도로 검증.

한 차종 자산만으로 여러 실차 사이의 시각적 차이까지 검증됐다고 보고하지 않는다. 초기 자리표시자는 실제 캐스퍼 자산으로 부르지 않는다.

### 구현 연결과 기존 코드 관찰

작업 도중 Kotlin/Gradle 기반 `app`·`core` 파일이 추가된 것을 확인했다. 다른 작업자의 변경이며 이번 작업은 수정하지 않았다. 현재 읽은 `DashboardView.kt`는 임시 차량 도형·차량 레벨·첫 성장 배지를 표현하고, `DriveEngine.kt`는 시험용 정산 로직을 가진다. **다음 차종 지급·전환, CSV ID 연동, 정식 아트가 구현됐다는 뜻은 아니다.** 코드에 있는 수치를 최종 게임 규칙으로 역확정하지 않는다.

제품 결정은 이 문서에서 관리하고, [기술 계약](02_SYSTEM_ARCHITECTURE.md)과 [검증 상태](06_VERIFICATION.md)는 해당 문서를 따른다. 차종 사실 목록은 CSV 한 곳에서 관리한다.

구현 전에 정할 최소 필드 **후보**:

| 분리할 데이터 | 후보 필드·관계 |
|---|---|
| 차량 사실 | CSV의 `vehicle_id` 참조. 필요하면 세대·파생형을 분리 |
| 성장 단계 | 단계 ID, 대표 `vehicle_id`, 다음 단계 참조, 승인된 해금 규칙 참조 |
| 사용자 성장 | 현재 단계·현재 차량 ID·성장값·정산 처리 이력 |
| 표현 | 차량 ID와 승인된 아트 연결, 정산/차고 표시 상태 |
| 선택 확장 | 이전 차 보유·색상·수집 이력은 확정 후 추가 |

차량 역할은 차종 교체 성장으로 정해졌고 단계 순서·레벨 해금·경험치 수치의 기준안도 있다. 스타리아·제네시스의 대표 모델, 교체 후 보유, 미기재 보상 규칙은 보완이 필요하다. 이번 요청은 문서 작업이므로 런타임 JSON/Kotlin 콘텐츠 표를 만들지 않는다. 구현 시 기존 기준안과 보완된 규칙을 Kotlin 프로젝트에 필요한 최소 정적 데이터로 옮기고, 문서·코드·화면에서 같은 `vehicle_id`를 쓴다. 화면에는 읽기 쉬운 표시명을 사용하고 내부 식별자와 연결한다. CMS·관리 서버를 새로 만들지 않는다.

### 1차와 이후 범위

- **현재 확정 방향:** 차량 단계 성장, 다음 차종 교체, 주행 중 게임 조작 없음, 주차 후 경험치·성장 결과 확인.
- **1차 제안:** 대표 한 차종의 시각 스타일과 정산 흐름부터 검토. 차종 교체 기능을 시연할 범위는 첫 자산 검토 후 정한다.
- **작성된 기준안:** 최초 지급·탈것 프롤로그, 단계 순서·레벨·XP·해금 수치, 보상·가챠·시즌 수치. 기존 PDF와 적용 문서를 기준으로 검토하며 처음부터 다시 기획하지 않는다.
- **추가 결정·확인:** 데모 시작 단계, 스타리아·제네시스 대표 모델, 일일 상한·보너스 포함 범위·가챠 보장 카운터, 교체 후 보유, 기능별 구현 범위, 자산 권리, 화면 스타일. 실제 성장 속도와 최종 밸런스는 미검증이다.
- **포함 범위·구현 순서 검토 대상:** 세부 차종·색상 수집, 가챠, 시즌, 온라인 도감·랭킹, 실제 탑승 차종 연동, 상용차·다른 브랜드. 사용자의 최대 포함 선호를 유지하며 팀 결정 없이 제외하지 않음.
