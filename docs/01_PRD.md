# 제품 요구사항 — 렌터카 가게

결정 반영일: 2026-11-03 KST(렌터카 방향), 2026-11-04 KST(#24 기능별 규칙), 2026-11-05 KST(#24 차량 게임 값), 2026-11-07 KST(#24 1차 차종·처분 기준), 2026-11-10 KST(1차 랭킹 범위). 기준은 사용자의 최신 채팅 결정이다. 이 문서는 제품 규칙의 단일 기준이며, **기획 합의와 구현 완료를 구분한다.** 기술 계약은 [구조 문서](02_SYSTEM_ARCHITECTURE.md), 화면은 [UI·UX 명세](09_UI_UX_SPEC.md), 실제 검증 결과는 [검증 문서](06_VERIFICATION.md)를 따른다.

## 방향과 변경 이력

드라이브 키우기는 **평소 이동을 차량 영입·수익으로 연결하고, 주차 후 차량을 모으고 렌터카 가게를 확장하는 차량용 방치형 경영 게임**이다. 자동차 수집과 작은 가게가 커지는 경험이 중심이다. 대상은 일상·장거리 이동의 결과를 게임 속 사업 성장으로 확인하려는 운전자다.

이전 PDF의 선형 차종 교체·탈것 프롤로그·전투·시즌을 현재 기획으로 사용하지 않는다. 차량은 레벨 상승으로 다른 차종으로 변하지 않고, 영입·중복 보유·대여·강화·매각의 대상이 된다. 이전 계산 검토는 [게임 조사 B부](03_GAME_BENCHMARK.md)의 과거 제안으로 보존한다. 원본 PDF와 기존 구현 기록은 수정하지 않는다. 아이디어 6안 PDF 이후의 렌터카 방향과 아래 사용자 답변이 이전 초안보다 우선한다.

**손님 이야기는 넣지 않고, 가게 꾸미기에 집중한다.** 손님 리뷰·단골 여부는 영업 결과 정보로 다루며 서사·대화 콘텐츠와 구분한다. 르르르는 가게 사장 역할이며 별도 성장 주체가 아니다. 사용권·표현 방식은 확인이 필요하다.

## 핵심 흐름과 성장 전후 변화

1. 주차·조작 허용 상태에서 가게 전체와 보유 차량, 쌓인 결과를 확인한다.
2. 목적지를 선택하면 거리 조건에 맞는 무작위 탁송 목록이 나온다. 플레이어는 수익 탁송 또는 구매 탁송을 고른다.
3. 출발하면 게임 화면·조작·게임 알림을 요구하지 않는다. 자동 기록은 제품 목표이며 플랫폼 허용과 실제 지속 수신은 미확인이다.
4. 실제 이동에 따른 기본 게임머니와 탁송 완료 보상을 구분한다. 탁송 보상은 도착을 확인한 뒤 지급한다.
5. 주차·조작 허용 후 사용자가 앱을 열면 결과를 확인하고, 새 차량·영업 수익으로 차량과 가게를 성장시킨다.
6. 결과를 바로 보지 않고 종료해도 다음 실행에서 저장된 결과를 확인한다. 확인 버튼은 보상 재지급 트리거가 아니다.

실제 탑승 차량과 영입할 게임 차량은 별개다. 실제 차종 식별이나 내비게이션 목적지 자동 취득을 지원한다고 가정하지 않는다. 탁송 미선택 이동의 기본 수익 유지와 출발 전 선택을 필수 절차로 만들지 않는 처리는 제안이며, 세부 동작은 확정 전이다.

## 확정 규칙

여기서 확정은 제품 방향의 합의이며 수치·SDK 지원·제출본 구현 완료를 뜻하지 않는다.

| 항목 | 결정 |
|---|---|

| 구매 탁송 변경 | 기존 결제금은 보류하고, 새 목록에서 차량을 고르면 **차액만 추가 결제 또는 환급**. 변경에는 취소 수수료를 부과하지 않음 |
| 수익 탁송 변경 | 새 목록에서 다시 선택하고 완료 보상은 **새 의뢰 기준**. 이미 운전한 거리는 기본 수익으로 지급됐으므로 별도 정산 없음 |
| 수익 탁송 포기 | **벌금 없음.** 완료 보상만 지급하지 않음 |
| 구매 취소 | 구매 대금에서 수수료 **10%**(시험값)를 공제하고 환급. 최소값은 미정 |
| 미도착 | 목적지가 아닌 곳에 주차하면 탁송은 진행 중으로 유지. **24시간**(시험값) 안에 도착하면 완료. 기한이 지나면 구매 탁송은 **수수료 없이 전액 환급**, 수익 탁송은 소멸(벌금 없음) |
| 기록 단절 | 확인된 구간만 기본 수익에 반영. 도착 증거가 부족한 탁송은 **확인 대기**로 보관하고 다음 주차 시 다시 확인. 끝내 확인되지 않으면 미도착 규칙 적용. 미수신 구간을 가짜 주행으로 채우지 않음 |

예상 경로 거리는 목록 생성에 쓰며 아직 운전하지 않은 거리를 기본 수익으로 지급하지 않는다. 탁송 예외 처리는 임의 몰수나 추가 운전 강요를 기본값으로 삼지 않는다.

| 차량 성장 | 개별 차량 레벨 사용. 레벨당 **대여료 +2%**·고객 선호도 상승(시험값). **최대 레벨은 모든 차량 20으로 동일.** 게임 연비 효과는 채택하지 않음 |
| 강화 | 기본 레벨업은 **게임머니**로 한다. 레벨업 1회 비용 = **차종 가격 × 2% × 현재 레벨 × 희귀도 비용 배율**(시험값, 조정 가능). **같은 차종 중복 차량**을 재료로 쓰면 재료 희귀도에 따라 **레벨 진행량 일반 100%·고급 150%·희귀 250%·전설 400%**(100% = 1레벨, 시험값)를 채우고 재료 차량은 소멸. 남는 진행량은 다음 레벨로 넘어간다. 최대 레벨 20을 넘는 진행량은 버리며, **이미 20인 차량에는 재료를 쓸 수 없음** |
| 차량 사용 중 제한 | **대여 중·반납 이동 중** 차량은 레벨업·강화·재료 사용·판매·폐차·수리 불가. **수리 필요** 차량은 수리·판매·폐차만 가능(레벨업·강화·재료 사용 불가). **영업 쉬기**는 언제든 켤 수 있고 대여 중이면 반납 후 적용 |
| 차고 용량 | 초기 **3칸**(시험값), 가게 확장으로 증가. 빈 칸이 없으면 **가챠를 막고** 공간 부족을 안내. 구매 탁송으로 도착한 차량은 이미 결제했으므로 **임시 보관함**에 **24시간** 보관하고 칸이 생기면 수령. 24시간 안에 수령하지 않으면 **수수료 5%를 공제하고 구매 대금 환급**(시험값) |
| 사고 | 가상 고객의 확률형 영업 위험. 대여 1회당 기본 **3%**(시험값)이며 모든 차량에 같은 기본 확률. **가상 고객의 면허 취득 기간이 짧을수록, 나이가 어릴수록** 사고율 상승: 면허 3년 이상 **3%**·1~3년 **4%**·1년 미만 **8%**, 25세 미만이면 **+5%p**, 최대 **13%**(시험값). 실제 운전자(유저)의 정보는 사용하지 않음. 가게의 대여 조건(나이·면허 제한) 설정 기능은 두지 않음 |
| 사고 결과 | 해당 대여 수익 **50%**, 차량은 **수리 필요** 상태(영업 불가). 차량을 영구 파괴하지 않음 |
| 수리 | 게임머니로 즉시 수리, 비용은 **차종 가격의 5% × 희귀도 비용 배율**(시험값). 수리 후 영업 가능 상태로 회복하되 **사고 1회당 대여료 −3% 영구 감소, 최대 −15%**(시험값). 사고 이력은 보존 |
| 판매 | 판매가 = **구매가의 60%**, 사고 1회당 **−5%p**, 최저 30%, 레벨 1 초과분 **레벨당 +1%p**(Lv20 사고 없음 79%, 시험값). 구매가는 실제로 낸 금액: 가챠 차량은 그 뽑기권에 실제로 낸 금액(구입 뽑기권 500, 할인 뽑기권은 할인가, 개업 선물·보상 등 무료 뽑기권은 0), 구매 탁송 차량은 결제액, 첫 지급 차량은 0 |
| 폐차 | **사고 3회 이상** 차량은 판매 불가, 폐차만 가능. 폐차 시 **구매가의 20%** 지급(시험값). 구매가 정의는 판매와 같다 |
| 가게 성장 | 외형·차량 보유 공간·보험 등급, 유명세에 따른 고객 요구 차량 폭과 계약 금액 확대 |
| 부대시설 | **주유소:** 보유 차량 5대에서 해금, 대여 1회마다 추가 게임머니 / **보험 시설:** 누적 고객 100명에서 해금, 사고 손실 절반 / **세차장:** 가게 레벨 3에서 해금, 리뷰 상승(해금 조건·효과 모두 시험값) |

### 앱 종료·휴식·복원

- 렌터카 영업은 주행 중과 앱 종료 후에도 이어지는 경험을 제공한다. 주행 중에는 정상 렌터카 수익을 적용한다.
- 주차 후 **첫 30분은 정상 수익**, 초과 시간은 **정상 수익의 30%** 로 감액한다(시험값). 앱을 꺼 둔 경우와 주차 중 앱을 켜 둔 경우에 같은 규칙을 적용한다. 앱을 켜 두는 것이 이득이 되지 않게 한다.
- 주차 후 수익 인정은 **최대 8시간**(시험값)까지이며 이후에는 쌓이지 않는다.
- 정상 수익 구간은 **마지막 주행이 끝난 시점부터 한 번만** 계산한다. 앱을 잠깐 열었다 닫아도 다시 시작되지 않는다.
- 기기 시계가 **뒤로 가면** 그 구간은 0으로 처리한다. **앞으로 크게 바뀌면** 최대 인정 시간까지만 계산한다.
- 1차는 **차량(기기) 1대 기준**이다. 여러 기기 동시 접속은 휴대폰 연동과 함께 후속 검토한다.
- 앱 종료 후의 영업은 시간 차이를 재접속 시 계산하는 방식으로도 구현 가능성을 검토한다. 실제 종료 상태에서 프로세스가 계속 실행된다는 뜻은 아니다.
- 차량 기록 누락 시에는 확인된 구간만 기본 수익에 반영하고, 도착 증거가 부족한 탁송은 확인 대기로 보존하며, 차량 신호와 무관한 영업은 별도로 계산한다. 미수신 구간을 가짜 주행으로 채우지 않는다.

### 시작 경험과 주요 기능

| 항목 | 상태 |
|---|---|
| 최초 차량 | 튜토리얼 후 캐스퍼·아반떼 중 선택하는 안. 두 차종이 후보이며 연식·트림·밸런스 미정. 희귀도는 **일반.** 선택은 확인 팝업 한 번 후 **취소 불가.** 최초 차량과 첫 보상은 프로필당 **한 번만** 지급 |
| 초기 상태 | 초기 재화 **1,000 게임머니**, 차고 **3칸**(시험값) |
| 첫 영업 보상 | 새 차 **뽑기권 1장.** 르르르의 친구가 찾아와 **개업 기념 선물**로 주는 연출(가게 개업 온보딩 연출이며 손님 서사와 구분) |
| 첫 성장 | 새 차 확보·주차 공간 확장·간판/가게 꾸미기를 경험하게 함. 순서·비용 미정 |
| 가챠 | 뽑기권은 **게임머니로 구입**(1장 **500**, 시험값), 현금 결제 없음. 확률 **일반 74.7% · 고급 20% · 희귀 5% · 전설 0.3%**(시험값). 희귀도를 먼저 뽑고, 가게 레벨에서 해금된 차종 중 하나를 골라 그 차량에 희귀도를 붙인다. 해금표(시험값): **Lv1 8종, Lv2 +6종, Lv3 +4종, Lv4 +2종**(차종 배치는 「1차 차종·가격 비율·해금 배치」). 레벨 조건과 차종 배치 조정은 B 담당(경민)이 가게 성장(#44)과 함께 조정 |
| 가챠 보장 | **30회 안에 희귀 이상 차량 1대 보장**(시험값). 모든 차종이 모든 희귀도로 나오므로 가챠를 열 수 있는 콘텐츠에는 해금된 차종이 최소 한 종 있으면 된다(#35). 적용 확률을 화면에 표시한다. 남은 횟수를 표시하고 뽑기 목록이 바뀌어도 횟수는 유지한다. 희귀 이상을 지급하면 카운터를 0으로 초기화한다. |
| 보장 후보 누락 | 콘텐츠 누락이나 버전 변경으로 해금된 차종이 없으면 이유를 안내하고 뽑기를 거절한다. 뽑기권·게임머니·보장 카운터는 유지한다. 잠긴 차량이나 낮은 희귀도 차량을 대체 지급하지 않는다. 후보 검증은 #35, 차감 전 거절과 상태 보존 검증은 #47에서 다룬다. |
| 퀘스트 | 일일 3개·주간 3개. **주행 거리 조건 없음.** 예: 결과 확인하기, 차량 1대 레벨업, 고객 5명 받기 |
| 업적 | 보유 차량 수·누적 고객 수·가게 레벨·도감 완성률. **운전 거리 업적 없음** |
| 도감 | **차종 × 희귀도** 칸(약 20종 × 4 = 약 80칸)마다 3단계: **미발견**(본 적 없음) / **발견**(탁송 목록·가챠 결과에서 본 적 있음) / **보유**(한 번이라도 소유). 판매·폐차·재료 소비 후에도 "보유했음" 기록 유지 |
| 가게 꾸미기 | 핵심 요구. 상세 규칙·제출 구현 범위·순서는 추가 구체화 |
| 차량 꾸미기 | 가게 꾸미기보다 낮은 우선순위. 필수 핵심으로 확정하지 않음 |
| 이벤트 | **주말 이벤트·시즌 제외.** 주행 수익 배수 이벤트는 두지 않음. 휴식 보상은 위 휴식 버프 규칙을 따름. 특별 고객 이벤트는 후보 |
| 랭킹 | 6개 부문: **가게 레벨, 도감 수집 수, 보유 차량 수, 누적 게임머니, 주행거리, 가장 비싼 차.** 「가장 비싼 차」는 보유 차량 중 **차종 가격 × 희귀도 수익 배율**이 가장 큰 값(시험값). 주행거리 부문은 하루 500km 상한을 적용하고 **매주 초기화.** 1차 포함/향후 온라인의 구분은 아래 「1차 랭킹 범위」를 따른다. 세 집계 기준은 아래 확정 사항을 따르며 나머지 미정 의미·필요한 동률은 별도 확인 |

| 손님 서사·시즌 | 제외. 리뷰·단골 정보와 이벤트까지 제외하는 뜻은 아님 |

### 1차 랭킹 범위

2026-11-10 사용자 직접 결정: **“내 기록 6개 지표와 시연용 랭킹 화면까지 구현하고, 실제 사용자 간 온라인 순위는 이후 연결.”** 기존 온라인 범위 미정을 이번 1차 포함/향후 연결로 구분한다. 1차 구현 대상은 위 여섯 부문의 내 기기 실제 기록 조회·표시와 명시 시연용 랭킹이다. 실제 사용자 간 온라인 순위는 1차 완료 게이트에 포함하지 않으며, 향후 연결로 남긴다. 이 결정은 범위 확정이고 현재 구현·검증 완료를 뜻하지 않는다.

내 기록은 실제 저장/조회 결과의 출처·기간·기준 시각과 가용성을 보존한다. 지표의 미정 의미·조회 실패·누락을 임의 0이나 정상값으로 보정하지 않는다. 기존 최고가 산식과 아래 확정한 집계 기준을 따른다. 이번 변경은 표시 집계 기준이며 실제 지급·지출·경제 산식을 바꾸지 않는다.

2026-11-10 추가 사용자 답변으로 다음 세 집계 기준도 확정했다. 기본 제안에서 판매·폐차 수익만 포함하도록 바꾸고 나머지 제안 기준을 유지한다.

| 지표 | 확정한 표시 집계 기준 |
|---|---|
| 누적 게임머니 | 영업·주행·의뢰·퀘스트 및 차량 판매·폐차의 **확정 수익 합계**. 지출해도 줄지 않으며 초기 지급·환급은 제외한다. 현재 잔액이나 미열람 정산 목록으로 대체하지 않는다. |
| 주간 주행거리 | **Asia/Seoul 월요일 00:00**부터의 거리. 하루 500km 상한을 적용해 **보상에 반영된 거리**만 집계한다. 전체 원시 주행거리·예상 경로 거리와 구분한다. |
| 도감 수집 수 | 한 번이라도 보유한 **차종×희귀도의 서로 다른 칸 수**. 판매·폐차·재료 소비 후에도 유지하며 발견만 한 칸은 제외한다. 같은 칸의 중복 개체는 중복 가산하지 않는다. |

시연용 랭킹은 예시 데이터임을 화면과 시연 설명에 명시하고 실제 내 기록과 분리한다. 예시 참여자/순위를 실제 사용자 경쟁 결과로 섞거나 내 온라인 순위를 1위로 만들어 표시하지 않는다. 이번 1차를 위해 새 서버·인증·외부 계정을 추가하지 않는다. 후속 온라인 연결 때 필요한 식별·동의·집계/동률·통신/오프라인 계약은 그때 검토하며, 이번 결정만으로 새 미래 구현 이슈를 일괄 생성하지 않는다. #58의 기존 담당/라벨·과거 검증 근거를 유지하고 1차 범위의 구현·통합 검증은 계속 필요하다.

최대한 많은 기능을 포함하려는 사용자 선호를 유지한다. 이 목록 전체를 1차 구현 확정이나 완료로 표시하지 않으며 임의로 핵심 기능만 남기고 나머지를 보류하지 않는다. 위 `보류` 항목은 #24에서 명시적으로 결정한 것이다.

## 안전·기술 확인과 남은 결정

주행 중 화면을 보게 하지 않는 것이 최우선이다. 게임 UI·입력·성장 연출은 주차와 플랫폼 UX 허용 상태를 함께 확인한 후 제공한다. 속도 0·브레이크 ON만으로 허용하지 않는다. 주행 중 자동 기록과 음성의 정책 상태는 [차량 API 조사](contest/03_VEHICLE_API.md)와 [음성 정책](contest/02_PLEOS_DEVELOPMENT.md)에 따른다. 기술적으로 API가 있다는 사실을 허용 근거로 쓰지 않는다.

| 남은 항목 | 정할 내용·이유 |
|---|---|
| 목적지·도착 | 목적지 입력 출처, 예상 거리 API, 도착 반경·증거·주차 조건. 도착과 단순 휴게소 정차를 구분(#13) |

| 탁송 수치 | 거리 구간·등장 확률·탁송 가격, 기본 주행 수익 배율, 희귀도 최저 등급 처리, 취소 수수료 최소값 |

### 안전 검토 사례

- `N km만 더 가면 희귀차` 안내는 추가 운전을 재촉하므로 주행 중 표시하지 않고 주차 후에도 거리 달성 재촉 문구를 쓰지 않는 표현안으로 검토한다. 거리별 목록 규칙 자체는 유지한다.
- 휴식 중 버프 시간이 줄지 않는 사용자 결정을 유지한다. 다음 출발 이후 만료 안내·중첩·추가 주행 유도는 별도 검토한다.
- 가상 사고는 실제 주행 평가와 분리하고, 급제동 같은 필요한 회피 행동을 벌하는 안전 지표로 표현하지 않는다.
- 주행 게임 화면 숨김은 기본 조건이다. 숨김 중 기록·음성의 허용은 #13 확인 전 검증 완료로 기록하지 않는다.
