## 4. 제출물과 GitHub

| 자료 | 1차 필수 여부 | 안내 |
|---|---|---|
| 공식 접수양식·기획서·동의서 | 필수 | 접수양식 자체가 기획서 |
| 시연 영상 | 선택 | 목업·프로토타입·화면 녹화 인정, 가산점 |
| GitHub 소스 코드 및 APK | 선택 | 개발 산출물 가산점 |
| 숏폼 링크 | 선택 | 본상 가산점 없음, 별도 이벤트 |

GitHub 제출 안내:

- 소스 코드와 APK를 함께 제공합니다. APK만 단독 제출하지 않습니다.
- 안내상 기본 위치는 저장소 `apk/` 폴더, 이름은 `팀명_앱이름_release.apk`입니다.
- 실행 가능한 release APK를 준비합니다. 용량 초과 시 GitHub Releases에 올리고 링크를 제공합니다.
- README에 앱 이름·한 줄 소개, 실행 방법, 테스트 환경·설정, 사용한 Pleos Connect 에뮬레이터 버전·화면 규격, APK 위치 또는 Release 링크를 기록합니다.
- 접수 마감까지 비공개 저장소를 사용할 수 있습니다. 심사 계정 초대는 필요 없습니다. 접수 메일에는 저장소 주소와 최종 커밋 해시를 적습니다. 심사는 이 커밋을 기준으로 진행합니다.
- 비공개로 접수한 저장소는 **2026-11-16까지 공개로 전환**하고 **2026-11-23까지 공개 상태를 유지**합니다. 전환하지 않으면 GitHub 개발 산출물 가산점이 반영되지 않습니다. 저장소 공개가 어렵다면 **접수 마감 전** 소스와 APK를 함께 압축한 파일의 다운로드 링크를 접수 메일로 제출할 수 있습니다.
- 이미 접수한 GitHub 제출의 최종 커밋 해시만 보완할 때는 최초 발신 주소에서 해시만 회신할 수 있습니다.
- 제출 안내 일부에 ‘제출 페이지에 입력’이라는 표현이 있지만, 접수 절차 및 양식의 경로는 이메일입니다. 링크·APK 경로를 접수자료에 명확히 기재합니다.

### 5.1 운영용 참가신청서

참가 단위·부문, 팀명, 앱명, 대표자와 구성원의 연락정보 및 역할을 작성합니다. 소속은 필수 기입이 아닙니다. 주민등록번호·신분증·상세주소는 요구하지 않습니다.

### 5.2 심사용 앱 소개

**대표자·구성원의 성명, 연락처, 이메일, 소속은 이 부분에 쓰지 않습니다.** 운영용 신청서와 구분합니다. 공유 링크·첨부자료도 개인정보·계정정보·개발자 실명이 노출되지 않도록 확인하라는 안내가 있습니다.

| 번호 | 항목 | 작성할 내용 |
|---|---|---|
| 1 | 앱 한 줄 소개 | 앱을 한 문장으로 설명 |
| 2 | 기획 배경 | 대상 고객의 필요·불편과 해결 필요성 |
| 3 | 주요 기능 및 차량 특화 요소 | 핵심 기능, 문제 해결, 차량에서 제공하는 경험 |
| 4 | 주요 사용 시나리오 | 사용자·상황·사용 흐름 |
| 5 | 개발 계획 | Pleos 구현 범위, SDK/API 사용계획 |
| 6 | 기대효과 및 발전 가능성 | 고객 가치, 타깃, 예상 MAU·유지율, 확대 계획 |
| 7 | 참고자료 | 화면 시안, 영상, GitHub 등 선택 자료 |
| 8 | 숏폼 링크 | 별도 이벤트 참여 시 기재 |

**소개 자료 분량 제한은 없습니다.** 작성란을 늘리거나 필요하면 별지를 추가할 수 있습니다. 접수번호는 운영사가 기입합니다.

### 5.3 동의서와 서명

개인정보 동의 안내와 대표자·팀원별 서명란으로 구성됩니다. CC 주소가 다른 수신자에게도 공개된다는 점을 팀원에게 안내하도록 되어 있습니다. 보관한 양식에 표시된 동의서 버전은 `1020 ver.`입니다.

## 6. 심사 기준과 단계별 의무

| 1차 평가항목 | 확인할 내용 |
|---|---|
| 차량특화성 | 모바일 대비 차량 환경의 가치, 주행·정차 맥락과 차량 기능의 결합 |
| 창의성 | 아이디어의 차별성, 고객 문제와 해결 방식의 명확성 |
| 기술 활용성 | SDK/API가 핵심 기능·경험에 적절하게 쓰이는지 |
| 사업성 | 타깃, 사용자 확보, 지속 사용과 확장 가능성 |

세부 배점은 공개되지 않았습니다. 개발 산출물에는 단계별 가산점이 있으나 구체적인 점수는 확인되지 않았습니다.

- 1차는 참가자별 동의·서명을 포함한 공식 접수양식으로 지원할 수 있습니다. 시연 영상과 소스·실행 가능한 Release APK는 선택 자료입니다.
- 1차 제출 산출물은 2차 전까지 보완할 수 있습니다.
- 2차 대상팀은 심사 전까지 실제 동작 가능한 앱을 완성하고 에뮬레이터 또는 기기로 시연해야 합니다. 제출 형식과 기한은 본선 안내에서 확인합니다.
- 수상작과 순위의 평가 기준 시점은 **2차 PT 제출·시연 결과물**입니다.
- 최종 선정팀은 전시 구동용 APK를 제출하고 현장 전시·시연에 참여합니다. 전시 영상 제작에도 협조합니다. OT [15:28](https://www.youtube.com/watch?v=na6tSJ44pWc&t=928s)은 이를 신규 기능 개발 기간으로 보지 않도록 명시합니다.
- 2차의 구체적인 심사 기준과 전시 준비 세부 준수사항은 추후 공지 예정입니다.
- **아이디어 특별상도 개발 산출물이 필요합니다.** 혁신성에 따라 완성도를 다르게 평가할 수 있다는 설명을 기획서만으로 최종 수상 가능하다는 뜻으로 해석하지 않습니다. [OT 06:14](https://www.youtube.com/watch?v=na6tSJ44pWc&t=374s)
- **생성형 AI는 기획·개발 전 과정에서 활용할 수 있습니다.** 참가자는 전체 구조와 로직을 이해하고 PT의 기술 질문에 직접 설명할 수 있어야 합니다. [OT 20:35~20:48](https://www.youtube.com/watch?v=na6tSJ44pWc&t=1235s)
- **공모전에서는 실차 시연을 지원하지 않습니다.** Pleos 에뮬레이터로 검증하도록 안내했습니다. 행사 현장 시연 의무가 실차 제공을 뜻하지는 않습니다. [OT 21:04~21:20](https://www.youtube.com/watch?v=na6tSJ44pWc&t=1264s)
