# 픽셀 그림 제작 기준서 (초안)

작성 2026-11-10 · 대상: 호열(지도·본관·화면 시안), 경민(차량·사람·시설·소품·아이콘, #171), 환석(앱 적용)

**공용 팔레트·크기 샘플:** 이 폴더(palette.png·palette.gpl·palette.hex·palette-swatches.png, size-sample@4x.png, ref-sprites/)

## 0. 전제

- 최종 화면은 **쿼터뷰 픽셀 그림**으로 교체한다([09 화면 명세 1절](https://github.com/Yaho03/drive-growth/blob/main/docs/09_UI_UX_SPEC.md#1-ui-구현-기준과-산출물)). 지금 앱 가게 그림(PR #161)은 기능 확인용 임시 그림이다.
- 그림은 **표현만** 바꾼다. 주차 칸 수, 시설 해금 조건, 가격 같은 게임 규칙은 PRD와 코드를 따른다. 그림 때문에 규칙을 바꾸지 않는다.
- 시안 그림 속 숫자(6/8, 16칸, 손님 100명 등)는 예시다. 실제 값은 아래 2절을 따른다.
- 제작 중인 그림(WIP)은 저장소에 올리지 않는다. 팀 확인이 끝난 그림만 PR로 올린다.
- 기준 그림: Claude Design 캔버스의 "2차" 보드(메인, 차량 시트, 사람 시트) — https://claude.ai/artifact/TR3ciN6J9HkLX2okkRuhRx

## 1. 공통 규칙

| 항목 | 규칙 |
|---|---|
| 시점 | 쿼터뷰(2:1 아이소메트릭). 바닥 타일 한 칸 = **32×16px** |
| 지도 원본 크기 | **640×464px**, 앱은 2배(1280×928)로 그린다. 480×320에는 주차 10칸과 시설 3곳이 함께 안 들어가서 넓혔다(`map/`) |
| 확대 | **정수 배율만**(2배·3배), 흐림 없이(nearest-neighbor). 남는 화면은 지도 바깥 풀밭으로 채운다 |
| 잘려도 되는 여백 | 지도 가장자리 40px는 화면 크기에 따라 잘릴 수 있다. 중요한 것은 안쪽에 둔다 |
| 팔레트 | 공용 **32색** 한 벌(`palette.*`, 2차 시안이 실제 쓴 32색 그대로). 추가 색은 팀 합의 후에만 |
| 외곽선 | 1px, 검정이 아닌 짙은 남색 계열 |
| 빛·그림자 | 빛은 왼쪽 위에서, 그림자는 오른쪽 아래로. 사람·건물·소품 아래에는 반투명 바닥 그림자를 둔다. **차에는 바닥 그림자를 그리지 않는다**(2026-11-12 @hoyeol903 결정: 시제품에서 차 밑 그림자가 어색해 보임) |
| 면 명암 | 윗면 > 왼면 > 오른면, 3단계 |
| 기준점(앵커) | 모든 스프라이트는 **바닥 중심점**을 기준으로 놓는다. 그림 파일에 기준점 위치를 함께 적는다 |
| 글자 | 그림 안에 글자를 넣지 않는다. 간판·표지판은 빈 판으로 그리고, 글자는 앱이 얹는다 |
| 로고 | 현대·제네시스 로고, 차명 글자, 번호판 문자는 그리지 않는다 |
| 파일 | 투명 배경 PNG, 원본 크기(확대하지 않은 것) |

## 2. 게임 규칙에 맞춘 그림 목록

### 2-1. 지도와 가게 건물 — 호열

| 그림 | 상태 수 | 게임 규칙 근거 |
|---|---|---|
| 지도 바닥(땅·도로·숲) | 1장 | 화면 밖까지 이어지는 느낌. 하늘·떠 있는 섬 없음 |
| 주차장 확장 구역 덮개 | 3장 | 가게 Lv1/2/3/4 → **주차 3/5/7/10칸**(PRD). 다음 레벨에서 열릴 구역을 울타리·풀숲·빈 표지판으로 덮는다 |
| 주차 칸 좌표 | 12칸 | 화면에 최대 12칸까지 그린다(현재 앱 코드). 칸마다 바닥 중심점 좌표를 표로 넘긴다 |
| 가게 본관 | 2종 | **Lv1** / **Lv2 이상(확장된 모습)**. 현재 앱은 레벨 1과 그 이상만 구분한다 |
| 본관 간판 판 | 1장 | 빈 판. "꾸미기"가 **간판 문구와 색**을 바꾸므로, 앱이 판 색을 입힐 수 있게 흰색 단색 영역을 따로 둔다 |

### 2-2. 시설 — 경민

시설은 **주유소, 보험, 세차장 3종뿐**이다. 2차 시안의 정비소는 게임에 없는 시설이라 쓰지 않는다(장식으로도 두지 않는다).

| 시설 | 해금 조건(시험값) | 그릴 상태 4가지 |
|---|---|---|
| 주유소 | 보유 차량 5대 | **잠김**: 빈 터 + 자물쇠 표지판 |
| 보험 시설 | 누적 손님 100명 | **지을 수 있음**: 빈 터 + 반짝이는 표지판 |
| 세차장 | 가게 레벨 3 | **설치됨**: 건물 + 직원 1명 자리 |
| | | **알 수 없음**(정보를 못 읽음): 빈 터 + 물음표 표지판 |

### 2-3. 차량 — 경민

**종류: 20종 × 4방향**(↘ ↙ ↗ ↖). ↙·↖는 ↘·↗를 좌우 반전해 만들어도 된다. 그래서 실제로는 2방향만 그리면 된다.

| 기본형 | 차종 |
|---|---|
| 경차 | 캐스퍼, 캐스퍼 일렉트릭 |
| 소형 SUV | 베뉴, 코나 |
| 세단 | 아반떼, 쏘나타, 그랜저, 아이오닉 6 |
| 고급 세단 | G80, G90 |
| SUV | 투싼, 싼타페, 팰리세이드, 넥쏘, 아이오닉 5, 아이오닉 9, GV70, GV80 |
| 승합 | 스타리아 투어러, 스타리아 라운지 |

- **만드는 순서:** 기본형 6개 → 차종별로 그릴·라이트·비율 차이를 더해요. 첫 차 후보인 **캐스퍼와 아반떼가 먼저**예요.
- **크기(확정, 2차 시안 기준 원본):** 경차 약 56×51, 세단 66×46, SUV 69×58, 승합 73×64, 고급 세단 73×48px. 차종별로 이 범위(가로 56~75px) 안에서 그린다. 이 숫자는 2차 시안의 바닥 그림자까지 잰 캔버스 크기다. 그림자는 그리지 않으므로 차 몸체는 이보다 조금 작고, 캔버스와 바닥 기준점은 그대로 둔다.
- **상세 화면:** 차고·상세·가챠 결과·도감용 192px 별도 그림은 **보류**(캐스퍼 시험 보류). 당분간 지도용 그림을 정수 배율로 키워 쓴다.
- **실차와 닮게 그리는 문제:** 실제 차종을 알아볼 수 있게 그린 그림을 출품물에 넣으려면 주최 측 확인이 필요하다(04 차량 조사, 약관 제7조). 확인 전에는 내부 시안으로만 쓴다.

**희귀도 표시: 4종** — 2차 차량 시트 방식을 채택한다. 차 그림은 그대로 두고 바닥 테두리만 바꾼다.

| 일반 | 고급 | 희귀 | 전설 |
|---|---|---|---|
| 점선 | 실선 + 은은한 빛 | 이중 테 + 반짝임 | 굵은 금테 + 반짝임 많이 |

색만이 아니라 모양으로도 구별되어야 한다.

**차량 활동 상태 표시** — 상태 아이콘은 16px, 경민이 그린다.

| 상태 | 지도 표현 |
|---|---|
| 대기 | 주차 칸에 주차 |
| 대여 중 | 칸은 비우고 "대여 중" 작은 표지 |
| 반납 중 | 도로에서 들어오는 차 |
| 수리 필요 | 주차 + 렌치 아이콘, 연기 한 줄기 |
| 영업 쉬기 | 주차 + 쉬는 중 아이콘 |

### 2-4. 사람 — 경민

| 그림 | 수 |
|---|---|
| 직원, 정비사, 손님 A, 손님 B | 4명 |
| 방향 | 앞(↘)과 뒤(↗) 2방향. ↙·↖는 좌우 반전 |
| 동작 | 서 있기 1프레임 + 걷기 2프레임 |
| 크기 | 서 있기 약 16×38px(그림자 포함, 2차 사람 시트 기준) |

정비사는 "수리 필요" 차 옆에 나타나는 사람이다. 정비소 건물은 만들지 않는다.

### 2-5. 소품·아이콘 — 경민

- **소품:** 나무 4종(침엽수, 둥근 나무, 꽃나무, 단풍), 가로등, 벤치, 화단, 자판기, 콘, 울타리, 빈 표지판
- **아이콘(16px):** 대여 중, 수리 필요, 쉬는 중, 잠김, 지을 수 있음, 알 수 없음, 새 소식

## 3. 화면별 시안 (Claude Design) — 호열

같은 픽셀 스타일로 차고, 차량 상세, 도감(차종 20 × 희귀도 4 = 80칸), 가챠, 정산, 탁송, 첫 실행, 랭킹 시안을 만든다. 숫자는 PRD 시험값을 쓴다. 예를 들어 뽑기권은 500이다.

## 4. 넘기는 방법

```
assets/
  map/        ground.png, cover_lv2.png, cover_lv3.png, cover_lv4.png, slots.csv
  building/   main_lv1.png, main_lv2.png, sign_board.png
  facility/   fuel_locked.png, fuel_available.png, fuel_installed.png, fuel_unknown.png (보험·세차장 동일)
  vehicle/    hyundai_casper_se.png, hyundai_casper_ne.png ...   (차종 ID는 앱 콘텐츠와 같게)
  rarity/     ring_common.png, ring_advanced.png, ring_rare.png, ring_legend.png
  people/     staff_se_stand.png, staff_se_walk1.png ...
  props/  icons/
  palette.png
```

- **파일 이름:** `대상_방향_상태.png`. 방향은 se(↘), sw(↙), ne(↗), nw(↖)로 적는다.
- **차 파일 이름:** 앱 콘텐츠의 차종 ID를 그대로 쓴다. 예: `genesis_g90`.
- **`slots.csv`:** `slot,x,y` 형식이다. 지도 원본 기준 바닥 중심점 좌표를 적는다.
- 각 폴더에 기준점 위치를 적은 메모를 함께 둔다.
- 다 그린 묶음은 미리보기 시트 1장과 함께 넘긴다. 팀 확인 전에는 저장소 밖에서 공유한다.

## 5. 환석님께 요청할 앱 쪽 변경 (기준서 확정 후)

1. **가게 화면에 넘기는 차 정보에 차종 ID, 희귀도, 활동 상태를 추가한다.** 지금은 차 이름과 상태 문구만 넘어온다.
2. **픽셀 그림은 정수 배율·흐림 없이 그린다.** 지금 코드는 1000×720 가상 화면을 소수 배율로 늘린다.
3. **시설의 잠김, 지을 수 있음, 알 수 없음 상태도 지도에 그린다.** 지금은 설치된 시설만 그린다.
4. **간판 판에 꾸미기 색을 입힌다.** 지금 임시 그림에는 이미 들어가 있다.
