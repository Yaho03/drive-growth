# 프로젝트 진행 계획

현재 단계: 준비와 기획 합의. 아래는 작업 순서이며 담당자·목표일과 제품의 미확정 규칙은 회의 후 정한다. 실제 진행 상태는 GitHub 이슈 라벨, 단계는 마일스톤을 기준으로 관리한다.

제품 기준은 [PRD](01_PRD.md), 기술 계약은 [구조 문서](02_SYSTEM_ARCHITECTURE.md), 실행 근거는 [검증 문서](06_VERIFICATION.md)를 따른다.

## 1. 지금 할 일 찾기

- [지금 착수 가능한 이슈](https://github.com/Yaho03/drive-growth/issues?q=is%3Aissue%20is%3Aopen%20label%3Aready)
- [선행 작업을 기다리는 이슈](https://github.com/Yaho03/drive-growth/issues?q=is%3Aissue%20is%3Aopen%20label%3Ablocked)
- [단계별 마일스톤](https://github.com/Yaho03/drive-growth/milestones)
- [통합 회의 #14](https://github.com/Yaho03/drive-growth/issues/14)

우선순위 P0–P3는 중요도이며 착수 순서가 아니다. 시작 조건을 충족했는지는 ready/blocked로 확인한다. 상태를 이 문서에 복사하지 않는다.

## 2. 단계별 목표와 산출물

| 마일스톤 | 목표·완료 기준 | 초기 작업 | 목표일 |
|---|---|---|---|
| M0 · 준비와 기술 확인 | 현재 구현·실행환경·기술 제약·제출 요구·자산 근거 정리. 미구현·미검증은 후속 작업으로 연결 | #11, #12, #13, #19, #20, #21 | 미정 |
| M1 · 기획 합의와 화면 설계 | 회의 결과와 후속 작업 정리, 합의한 핵심 화면 명세 준비 | #14, #18 | 미정 |
| M2 · 핵심 기능 구현 | 합의한 기록·정산·저장·차종 교체와 추가 기능 구현 및 해당 검증 | 회의 후 작업 생성 | 미정 |
| M3 · 통합 검증과 제출 준비 | 합의한 제출 범위 검증, 기획서·화면·시연 자료의 실제 결과 일치 확인 | 회의 후 작업 생성 | 미정 |

M0가 모두 끝나야 M1 회의를 할 수 있는 것은 아니다. 이슈별 시작 조건을 따른다. M2·M3에는 준비되지 않은 구현 이슈를 미리 채우지 않는다. 해당 마일스톤이 비어 있어도 단계 완료가 아니다. 공식 기한은 [공모전 안내](contest/01_CONTEST_GUIDE.md)를 따르며 팀 목표일과 구분한다. 1차 제출 수준은 #14에서 정하고 이후 확장 기능 때문에 1차 준비 전체를 막지 않는다.

## 3. 작업 순서와 병렬 진행

| 작업 | 시작 조건 | 병렬 진행·인계 |
|---|---|---|
| [#11 현황 확인](https://github.com/Yaho03/drive-growth/issues/11) | 없음 | #12·#19·#21과 병렬. 코드 현황을 #20에 전달 |
| [#12 환경 준비](https://github.com/Yaho03/drive-growth/issues/12) | 환경 점검은 바로 시작. 실행 소스는 #11 담당과 확인 | #11과 병렬. 실행 가능한 환경 확보 후 #13 시작 |
| [#19 자산 조사](https://github.com/Yaho03/drive-growth/issues/19) | 공개 자료 조사 조건 없음 | #14·#18에 사용 가능·미확인 자산 전달 |
| [#21 제출 초안](https://github.com/Yaho03/drive-growth/issues/21) | 없음. 미확정 내용은 질문으로 표시 | #14에 양식·누락 목록 전달. 최종 자료는 M3 후속 작업 |
| [#14 통합 회의](https://github.com/Yaho03/drive-growth/issues/14) | 준비·개최 조건 없음. 확보된 조사 결과를 사용 | 미확인은 잠정·보류 처리. 제품 결정·역할·후속 작업 정리 |
| [#13 차량 연동 검증](https://github.com/Yaho03/drive-growth/issues/13) | #12의 실제 시험 환경 확보 | #20과 파일을 나눠 병렬 검증 |
| [#20 정산·저장 검증](https://github.com/Yaho03/drive-growth/issues/20) | #11 코드 확인. 앱 실행 시 #12 환경도 필요 | #13과 병렬, 저장·엔진 동시 수정은 조율 |
| [#18 화면 명세](https://github.com/Yaho03/drive-growth/issues/18) | #14에서 핵심 흐름·제한 원칙·설계 범위 합의 | #19와 병렬. 미확인 자산은 자리표시자 사용 |

선행 이슈가 닫혔다는 사실만으로 조건 충족을 판단하지 않는다. 실행 실패 기록으로 종료했거나 결정이 보류됐으면 해당 결과를 기다리는 작업은 계속 대기한다. 회의용 간단한 그림은 #14 준비물이며 #18의 정식 화면 설계와 구분한다.

## 4. 전체 기능 범위와 이전 묶음

기능 기준은 PRD에서 관리하고 아래는 추적용 목차다. 상위 이슈를 닫는 것은 기능 제외·구현 완료가 아니다. 이전 이슈 본문은 참고 이력이며 현재 착수 판단에는 사용하지 않는다.

| 관리할 분야 | 이전 묶음 | 현재 인계 |
|---|---|---|
| 기획·제출 | #3 | #14·#21, 최종 자료는 M3 |
| 개발 기반 | #4 | #11·#12 |
| 차량 연동 | #5 | #13, 후속 구현은 M2 |
| 기록·정산·저장·복원 | #6 | #20, 부족한 구현은 M2 |
| 성장·차종 교체·전투·이야기 | #7 | #14에서 결정 후 M2 작업 생성 |
| 도감·꾸미기·가챠·퀘스트·시즌 | #8 | #14에서 범위·규칙·순서 결정 |
| 랭킹·음성·휴식 안내 | #9 | #14에서 범위·지원·데이터 조건 결정 |
| 화면·공통 자산 | #10 | #18·#19 |

## 5. 역할·일정과 변경 기록

담당·확인자·목표일은 #14에서 합의 후 이슈의 담당자와 이 문서의 큰 일정에 반영한다. 현재는 미정이며 분담을 확정한 상태가 아니다. 공유 파일 담당과 통합 검증 시점도 함께 정한다.

2026-11-03: 사용자 요청으로 상위 묶음 #3–#10을 이 문서의 목차로 옮기고, 회의 안건 #15·#16·#17·#22를 #14로 통합한다. 통합된 이슈는 완료 성과가 아닌 `not_planned` 사유로 닫고 원래 본문과 대체 위치를 보존한다. 열린 작업은 8개로 정리하며 이후 제품 결정·구현·검증 상태를 바꾸면 CONTRIBUTING.md의 동기화 절차를 따른다.
