# 프로젝트 진행 계획

현재 단계: 준비와 기획 합의. 아래는 작업 순서이며 담당자·목표일과 제품의 미확정 규칙은 회의 후 정한다. 실제 진행 상태는 GitHub 이슈 라벨, 단계는 마일스톤을 기준으로 관리한다.

제품 기준은 [PRD](01_PRD.md), 기술 계약은 [구조 문서](02_SYSTEM_ARCHITECTURE.md), 실행 근거는 [검증 문서](06_VERIFICATION.md)를 따른다.

## 1. 지금 할 일 찾기

- [지금 착수 가능한 이슈](https://github.com/Yaho03/drive-growth/issues?q=is%3Aissue%20is%3Aopen%20label%3Aready)
- [선행 작업을 기다리는 이슈](https://github.com/Yaho03/drive-growth/issues?q=is%3Aissue%20is%3Aopen%20label%3Ablocked)
- [단계별 마일스톤](https://github.com/Yaho03/drive-growth/milestones)
- [통합 회의 #14](https://github.com/Yaho03/drive-growth/issues/14)

우선순위 P0–P3는 중요도이며 착수 순서가 아니다. 시작 조건을 충족했는지는 ready/blocked로 확인한다. 상태를 이 문서에 복사하지 않는다.

## 2. 단계별 목표와 산출물

| 마일스톤 | 목표·완료 기준 | 초기 작업 | 목표일 |
|---|---|---|---|
| M0 · 준비와 기술 확인 | 현재 구현·실행환경·기술 제약·제출 요구·자산 근거 정리. 미구현·미검증은 후속 작업으로 연결 | #11, #12, #13, #19, #20, #21 | 미정 |
| M1 · 기획 합의와 화면 설계 | 회의 결과와 후속 작업 정리, 합의한 핵심 화면 명세 준비 | #14, #18 | 미정 |
| M2 · 핵심 기능 구현 | 합의한 기록·탁송·영업·정산·저장·가게 성장과 추가 기능 구현 및 해당 검증 | 회의 후 작업 생성 | 미정 |
| M3 · 통합 검증과 제출 준비 | 합의한 제출 범위 검증, 기획서·화면·시연 자료의 실제 결과 일치 확인 | 회의 후 작업 생성 | 미정 |

M0가 모두 끝나야 M1 회의를 할 수 있는 것은 아니다. 이슈별 시작 조건을 따른다. M2·M3에는 준비되지 않은 구현 이슈를 미리 채우지 않는다. 해당 마일스톤이 비어 있어도 단계 완료가 아니다. 공식 기한은 [공모전 안내](contest/01_CONTEST_GUIDE.md)를 따르며 팀 목표일과 구분한다. 1차 제출 수준은 #14에서 정하고 이후 확장 기능 때문에 1차 준비 전체를 막지 않는다.

2026-11-03 확인한 [OT 전체 요약](contest/05_ORIENTATION_NOTES.md)을 #12·#13의 SDK 조건·시연 환경, #14의 AI 활용과 기술 설명 준비, #21의 제출 조건 확인 자료로 사용한다. 1차와 PT의 완료 의무는 [공모전 안내](contest/01_CONTEST_GUIDE.md), 개발 승인과 실제 API 가용성은 [개발 자료](contest/02_PLEOS_DEVELOPMENT.md)를 기준으로 구분한다. 원격 이슈의 반영 여부는 이번 문서 조사에서 확인하지 않았다.

선행 이슈가 닫혔다는 사실만으로 조건 충족을 판단하지 않는다. 실행 실패 기록으로 종료했거나 결정이 보류됐으면 해당 결과를 기다리는 작업은 계속 대기한다. 회의용 간단한 그림은 #14 준비물이며 #18의 정식 화면 설계와 구분한다.

2026-11-03 문서 반영. 아래는 기존 작업에 전달할 확인 사항이며 원격 이슈 본문·상태를 수정한 결과가 아니다. 담당·목표일은 미정이다.

정책 확인과 독립적인 환경·저장·주차 화면 설계는 병행할 수 있다. 주행 중 실행 모델의 최종 확정에는 정책 근거와 실제 수신·수명주기 검증이 필요하다. 전체 개발을 승인 대기로 돌리거나 추가 기능을 임의 제외하는 계획이 아니다.

2026-11-03 개발 기반 정리: [기술 설계의 채택·결정 대기](02_SYSTEM_ARCHITECTURE.md#개발-기반-결정)와 [버전 기준](05_DEVELOPMENT_SETUP.md#개발-기반과-버전-기준)을 #12·#14·#18·#20의 참고 기준으로 연결했다. 제품 기능·날짜·담당은 새로 확정하지 않았다. 미정 기능의 구현 이슈를 미리 생성하지 않으며, 해당 기능의 동작·실패 처리·완료 조건이 합의되면 구체화한다. 원격 이슈는 이번 문서 작업에서 조회·변경하지 않았으므로 본문 반영 여부는 미확인이다.

## 5. 역할·일정과 변경 기록

담당·확인자·목표일은 #14에서 합의 후 이슈의 담당자와 이 문서의 큰 일정에 반영한다. 현재는 미정이며 분담을 확정한 상태가 아니다. 공유 파일 담당과 통합 검증 시점도 함께 정한다.

2026-11-03: 사용자 요청으로 상위 묶음 #3–#10을 이 문서의 목차로 옮기고, 회의 안건 #15·#16·#17·#22를 #14로 통합한다. 통합된 이슈는 완료 성과가 아닌 `not_planned` 사유로 닫고 원래 본문과 대체 위치를 보존한다. 열린 작업은 8개로 정리하며 이후 제품 결정·구현·검증 상태를 바꾸면 CONTRIBUTING.md의 동기화 절차를 따른다.

## 렌터카 방향 변경의 후속 연결

2026-11-03: 최신 사용자 결정을 PRD·기술 계약·화면·검증 계획에 반영했다. 구현 이슈를 새로 생성하거나 원격 이슈를 조회·수정하지 않았다. 아래는 인계 목록이며 원격 반영 완료 표시가 아니다. 담당·목표일은 미정이다.

| 대상 | 후속 반영할 내용·선행조건 |
|---|---|
| #14 | PRD의 남은 결정: 경제 수치·도착/실패·시간·추가 기능별 제출 범위. 사용자 확정 항목을 다시 미정으로 돌리지 않음 |
| #13 | 목적지·예상 경로 거리·도착 증거 접근 가능성, 기록 누락·주행 중 수명주기 검증 |
| #20 | 구매·환급·강화·개체 처분의 원자성, 영업 시간 구간 정산·재실행 중복 방지. 미정 수치 확정 후 기대값 고정 |
| #18·#19 | 가게 중심 화면·보유 차량 보기·탁송 선택·영업 결과·사장 역할 자산. 실제 차량·로고·캐릭터 권리 확인 |
| #21 | 원본 PDF 이후 변경된 렌터카 방향을 제출 수정본에 반영. 실제 구현·검증 수준에 맞춰 설명 |

이전 #7·#8의 제목·본문에 남은 전투·이야기·시즌은 현재 확정 기능으로 읽지 않는다. 기존 완료 이력은 보존하고 실제 이슈 수정 권한이 주어지면 변경 사유와 대체 기준을 연결한다. 현재 문서 합의만으로 M2 구현 완료나 M3 제출 준비 완료로 전환하지 않는다.
