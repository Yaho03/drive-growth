# 제품 요구사항과 기획 결정

이 문서는 제품 범위·화면·콘텐츠 결정의 기준이다. 기획서의 제안, 사용자 확정, 구현, 실행 검증을 구분한다. 공식 API 근거는 [차량 API와 설계 조건](공모전/03_차량_API와_설계조건.md), 차종 자료는 [vehicles.csv](data/vehicles.csv)에서 관리한다.

이번 원격 초기 게시에는 문서와 기본 설정만 포함한다. 아래 구현 관련 설명은 별도 로컬 작업의 기록이며 `app/src`·`core/src` 소스는 이번 게시 대상이 아니다. 이후 소스 게시 시 실제 구현과 검증 상태를 다시 맞춘다.

## 최신 기획서 확인

2026-11-03 작성된 `docs/공모전/드라이브키우기_게임기획서.pdf`의 8페이지 전체 텍스트와 3페이지 성장 도표를 확인했다. 원본은 수정하지 않았다. 파일 식별 SHA-256: `ed3e5a08d92d69ab6e46505fdf9e054992b14e1a32bf9b270ae628dc8eaf5ceb`.

새 문서는 **팀 공유용 초안**이다. 문서 안의 제안과 체크리스트를 사용자 실행 지시 또는 구현 완료로 취급하지 않는다.

## 사용자 결정과 남은 확인

- 공통 확정: Pleos Connect 차량용 앱, 주행 중 자동 기록·게임 조작 없음, 주차 후 정산·성장·수집 확인, 저장·복원. 게임의 운전 평가를 검증된 안전성 지표로 표현하지 않는다.
- 이전의 ‘같은 차종을 계속 키움’은 최신 사용자 답변으로 대체되었다. 차량 레벨·차종이 운전 평가를 유리하게 하지 않는 원칙은 유지한다.
- 최신 PDF 제안: 르르르 주인공, 몬스터 자동 전투, 뚜벅이→탈것→현대차→제네시스의 선형 성장, 높은 차종의 공격력 증가.
- **최신 사용자 확정(2026-11-03):** 새 기획서처럼 캐스퍼에서 아반떼·제네시스 등 다음 차종으로 바뀌는 성장 구조다. 차종 조사의 목적도 이 단계 구성이다. 단계·경험치·가챠·보상 수치는 새 기획서와 [방치형 게임 적용 문서](idle-game-application.md)에 기준안이 작성돼 있다. 이를 토대로 미기재 규칙을 보완하며, 최종 밸런스 검증과 캐릭터·이미지 사용권 확인은 별도로 남는다. [차량 게임 기획](vehicle-game-design.md)과 [차량 조사 범위](vehicle-research.md)를 참조한다. 이번 차량 정리 요청은 문서 작업이며 구현 완료를 뜻하지 않는다.
- 사용자 범위 선호: 휴게소 음성, 랭킹, 수집, 기능 퀘스트 등을 임의로 보류하지 않고 최대한 포함한다. 구현 순서를 정하는 것과 기능을 제외하는 것은 다르다.

## 새 기획의 기능 검토 범위

| 기획서 내용 | 구현 전에 필요한 결정·근거 |
|---|---|
| 스토리·르르르·몬스터 전투 | 핵심 방향 확인, 캐릭터·외형 사용 조건, 전투와 운전 평가 분리 |
| 19단계 진행·차종 해금 | 뚜벅이를 포함한 19상태/탈것·차종 18단계임을 명시, 차종 순서·라인업 확인 |
| 무료 가챠·천장·중복 부품 | 풀·확률·천장 카운터·중복 전환 수량, 추첨과 저장의 단일 처리, 재실행 중복 방지 |
| 시즌 패스·정기 이벤트 | 시즌 기준 시각·종료 정산·중복 보상 방지, 미접속·시각 변경 처리 |
| 튜토리얼·챕터·일일·주간·업적 | 차량별 지원 여부, 안전하게 자동 감지 가능한 조건, 미지원 기능 대체 경로 |
| 음성·휴게소 권유 | TTS/STT 실행 확인, 경로상 휴게소 데이터 출처, 실제 휴식 판단, 중복 권유·거절 처리 |
| 프로필·도감·꾸미기·랭킹 | 저장 대상과 프로필 구분, 랭킹 지표·대상·동기화 범위 확정 |

위 항목은 검토·개발 대상이며 구현 완료 목록이 아니다. 공개 랭킹과 기기 내 랭킹은 다른 기능이다. 승인 없이 기기 내 랭킹을 공개 랭킹의 완성으로 대체하지 않는다.

## 수정 제안과 검증 조건

1. **필요한 제동을 벌주지 않는다.** 속도 변화만으로 위험운전·불필요한 급제동을 판정할 수 없다. 급제동 시 HP 감소, ‘급제동 0회로 100km’ 성공 조건은 재설계한다. 분석 이벤트와 게임 보상 판정을 분리한다.
2. **불필요한 주행·기능 사용을 요구하지 않는다.** 크루즈 켜기·차로 변경을 필수 튜토리얼 관문으로 두지 않는다. 상황·지원 여부에 따른 건너뛰기와 주차 중 설명으로 대체하는 안을 검토한다. 거리·연속일·시즌 마감·주말 권유가 추가 운전을 유도하는지도 확인한다.
3. **관측 신호와 해석을 구분한다.** 깜빡이 신호는 차로 변경 완료, 와이퍼는 강우, 전조등은 야간, 오래 운전한 시간은 실제 졸음의 확정 근거가 아니다. 보스는 게임적 표현이며 실제 위험 진단으로 표시하지 않는다.
4. **정차와 주차를 구분한다.** 10절의 ‘주차·정차 중 안내’는 13절의 신호 대기 조작 금지와 충돌한다. 조작·가챠·상세 퀘스트는 확인된 주차 상태와 시스템 UX 허용 조건을 함께 충족할 때만 제공한다.
5. **전투 성장과 평가의 관계를 정의한다.** 높은 차종의 공격력이 처치 수·EXP·시즌 진행도를 늘린다면 보상에 간접 차이가 생긴다. 운전 평가·게임 진행·경쟁 순위를 각각 정의하고 외형 가챠가 이 계산에 영향을 주지 않는지 검증한다.
6. **권리 확인과 공개 범위를 구분한다.** 차종 조사 자료는 게임 자산 사용 허가가 아니다. 원본 팀 공유 PDF에는 작성자 이름이 있으므로 심사 제출본은 공식 익명 소개 조건에 맞춰 별도로 준비한다. 문의 이메일은 자동 발송하지 않는다.

## 수치 확인 결과

- `다음 레벨 필요 EXP = 60 + 20 × 현재 레벨`을 독립 계산한 결과, 표에 적힌 Lv4~80의 모든 단계 진입 누적 EXP와 일치했다. Lv10=1,440, Lv20=4,940, Lv80=67,940.
- 30km/일 × 평균 12EXP/km = 360EXP/일, 주 5일이면 1,800EXP/주라는 가정에서 Lv10 약 4주행일, Lv80 약 37.7주는 산술상 맞는다. 실제 측정 결과가 아니다.
- 몬스터·휴식·퀘스트 보상과 일일 상한을 합친 실제 성장 속도는 아직 검증하지 않았다. 상한과 평균 12EXP/km에 포함되는 보상 범위를 정해야 한다.
- MAU 표의 곱셈은 맞지만 탑재 대수·설치율·활성률은 가정이다. D1/D7/D30 ‘시뮬레이션’ 값은 이 PDF에 재현 모델·입력·실행 근거가 없어 검증 결과로 사용할 수 없다.
- 현재 핵심 엔진의 20XP·단순 레벨 규칙은 초기 기술 검증용이며 새 기획의 성장표를 구현한 상태가 아니다.

## 현재 화면 구현 상태

`DashboardView`에는 임시 차량 도형을 사용하는 홈·주행 제한·정산·차고·기록·튜토리얼·기기 내 랭킹 표현이 있다. 독립 Kotlin 컴파일만 확인했으며 Activity 연결·실데이터·화면 실행 검증 완료를 의미하지 않는다. 새 기획의 3개 주요 화면(차고→주행→정산)에 도감·가챠·랭킹을 하위 화면으로 배치하는 안을 검토한다.
